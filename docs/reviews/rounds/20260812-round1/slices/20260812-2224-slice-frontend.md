Baseline is green (webapp: vitest 45/45 passed, `vite build` succeeded; desktop: `node --check` passed on main.js/preload.js/release.js) and all frontend↔backend contracts I checked (meetings session/events/messages/advance, control run_now/save_settings, knowledge_drafts, mailbox, dashboard) match. Full review comments:

- [P2] Refetch full message history after SSE reconnect in useMeetingStream — E:\code\novel-editorial\webapp\src\lib\use-meeting-stream.js:80-81
  The hook's own doc comment promises "重连后依赖消息表为真相（SSE 只做增量）", but `es.onerror` (webapp/src/lib/use-meeting-stream.js:80-81) only sets an error string: there is no `onopen` handler and no re-call of `getMeetingMessages(sessionId)` when EventSource reconnects. Any `message` events published while the connection is down (e.g. the desktop main.js auto-restart of the API after a crash) are written to `meeting_messages` but never pulled into the live view, so they stay missing until a full page reload; the "实时连接中断" badge also persists after a successful reconnect.

- [P2] Clear finished session so meetings page returns to start form — E:\code\novel-editorial\webapp\src\pages\MeetingsPage.jsx:99-100
  In rounds mode (the default), after the user clicks 结束会议 (`advance(true)`) or the backend finishes/fails the session, the poll at webapp/src/pages/MeetingsPage.jsx:99-100 detects `finished`/`failed` and calls `clearInterval(timer); refresh()` but never `setSession(null)`. The page stays stuck on the finished live-room view (badge 已完成, input row and 结束会议 button still rendered), and the 发起会议 form only returns after navigating away and back or reloading — `advance` on a finished session then fails with "当前状态不是等待输入". Free mode is unaffected because `FreeLive` calls `onEnded`.

- [P2] Commit version bump in desktop release script before tagging — E:\code\novel-editorial\desktop\release.js:132-133
  desktop/release.js:70-76 writes the bumped version into `desktop/package.json` via `writePackageVersion`, but the script never runs `git add`/`git commit` before `git tag v${version}` + `git push origin v${version}` (lines 132-133). The pushed tag therefore points to a tree whose package.json still has the old version, while the built installer embeds the new one. On a fresh clone at that tag the next `node release.js` bumps from the stale version and is rejected by the stale-version guard ("refusing to release stale version"), so the release pipeline breaks until the bump is manually committed.

- [P3] Remove dead closeToTray IPC channel in desktop preload — E:\code\novel-editorial\desktop\preload.js:11-11

The exposed API misleads future callers into thinking close-to-tray is handled (the actual hide-to-tray path is the `win:close` handler), so either register the listener or drop the binding.

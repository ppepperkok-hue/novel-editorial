### 高危

1. **n8n 监听 0.0.0.0:5678**：管理界面暴露到所有网卡，局域网内可访问。
   已修复：`~/.n8n/.env` 增加 `N8N_LISTEN_ADDRESS=127.0.0.1`，重启后仅监听本机。

   B 章可能已发布但「合并/汇总/记录」不执行，数据库缺 B 章，次日章节号错乱。
   已修复：
   - 质量门/校验发布/解析草稿改为「失败标记 + 短路」，不再抛错；

3. **数据库无自动备份**：backup.py 存在但从未被调用。

## 二、多 Agent 策略（本轮落地）

参考 oh-story 的七 Agent 体系与 sumeru 的分模块编排，按「月预算 100 元、
每天两章」的约束，把流水线升级为多角色协作，全部复用 DeepSeek 已有 key：

### 现有角色（继续保留）

| Agent | 节点 | 职责 |
| --- | --- | --- |
| 策划官 | Planner出大纲 | 生成/增量更新故事圣经与两章细纲 |
| 世界观守护 | 守护细纲 → 解析守护（新） | 对照圣经检查细纲 OOC/吃书/伏笔/时间线，输出必须遵守的 constraints |
| 叙事写手 | 写手A/B | 按细纲 + 角色卡 + constraints 写正文 |
| 文字编辑 | 润色A/B | 去 AI 味、标点、节奏 |
| 逻辑审稿 | 审稿A/B | 六类底线问题 + 风格检查 |
| 读者体验审稿 | 读者审稿A/B（新） | 以普通读者口味评分：追读欲/钩子/情绪满足 |
| 记忆官 | 提炼剧情A/B → 整理剧情A/B | 每章提取摘要、角色状态、事件、伏笔台账 |

### 新增协作机制

1. **守护 Agent 不直接改稿，只输出约束**：`constraints` 注入写手提示词，
   失败时降级为空约束，不阻断日更（`onError: continueRegularOutput`）。
2. **双审稿串联**：逻辑审稿（能看不能读）→ 读者审稿（能读不能挑逻辑），
   质量门要求两者同时通过：`review.passed && reader.would_read_next &&
   reader.score>=7 && reader.hook_rating>=7`；读者审稿缺失时降级放行并记录。
3. **热点注入**：Planner/写手共享记忆包里新增「近期热点」，趋势元素可织入当前章。

### 每日新增成本

守护 1 次 flash + 读者审稿 2 次 flash，约每天 3 次轻量调用，
按 DeepSeek flash 计价估算每天不足 0.1 元，远在预算内。

# 最小架构范围（Minimum Scope）

只搭建支撑 M1（最小可验证版本）的架构；其余功能留到以后按接入规则增量加入。范围决策与可执行单元一一对应。

## 本期架构范围（做）

支撑 M1 的横切能力：

- **配置加载**：环境变量（`NOVEL_*`）+ 本地配置文件（TOML）+ `.env` 支持；支撑 U1、U5。
- **CLI 路由**：Typer 命令框架与统一入口；支撑 U1–U15 全部命令。
- **数据访问层**：SQLAlchemy 2.0 模型 + Alembic 初始迁移；每部作品独立 SQLite 文件 + 全局库；支撑 U2、U3、U4、U8、U11、U14。
- **LLM 客户端**：统一调用层，支持真实 key 与模拟模式；支撑 U5、U6、U7、U9。
- **事件结构**：统一事件 JSON 契约（对话、草稿、质量门、决策）；创作日志与可见性共用；支撑 U6、U11、U15。
- **质量门基础**：词表命中与密度检测、报告与拦截；支撑 U13。
- **结构化日志与错误处理**：系统日志与创作日志分离，异常有明确类型与错误码；支撑 U1–U15。
- **测试骨架**：pytest + 验证命令；支撑全部单元的验收。

## 本期不做（延迟）

- FastAPI 服务与 SSE（面板阶段启用）。
- 图形面板与桌面应用（后置）。
- 伙伴完整档案、立场与拒绝、私有记忆（M2：U16–U18）。
- 分层视图与按需检索、叙事追踪（M2：U19–U20）。
- 质量门完善（句式重复、风格一致性）与 AI 味定位改写建议（M2：U21–U22）。
- 伙伴状态沉淀（M2：U23）。
- 可见性三扇窗完整形态（M3：U26–U27）。
- 多作品并行的高级管理界面（先保证数据隔离）。

## 范围决策记录

| 决策 | 理由 | 对应单元 |
| --- | --- | --- |
| 每作品独立 SQLite 文件 + 全局库 | 作品隔离天然成立，备份即复制文件 | U2、U14 |
| LLM 客户端内置模拟模式 | U5 验收要求模拟 key 可跑通，端到端演示不依赖真实 key | U5、U15 |
| 事件契约先于面板定义 | 创作日志与可见性共用同一结构，避免后期重造 | U6、U11、U15、F17–F19 |
| 只做基础质量门 | M1 验证拦截逻辑，检测维度随 M2 扩展 | U13 |
| Alembic 只建初始 baseline | 本期无历史迁移需求，后续迁移随功能增加 | U1–U15 |

## 验收门

- 范围能支撑 M1 端到端跑通，无“顺手搭一下”的机制。
- “本期不做”清单明确，且不阻塞 M1。
- 用户确认后进入通用规则。

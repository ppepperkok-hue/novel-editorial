This also inflates `updated_at` so `snapshot()` ordering and the `updated` signal report fake updates. `sync_from_bible` avoids this via `_upsert_if_changed`; chapter sync should skip when stored content is unchanged.

- Fix 4-char stacking heuristic false positives in ai_taste_check — E:/code/novel-editorial/tools/ai_taste_check.py:78-89
  The 'parallel four-character stacking' heuristic (tools/ai_taste_check.py:78-89) counts every run of ≥8 consecutive hanzi characters as one occurrence (`re.finditer(r"[\u4e00-\u9fff]{4}", text)` plus adjacent-start counting), so any two plain narration segments of ≥8 characters separated by punctuation trigger `疑似四字排比堆砌 2 处`. Reproduced: '她站在窗前看了很久，心里想着明天该如何开口解释这件事。' and '林深走进大殿的时候，所有人都安静下来不敢出声。' both report 2 occurrences despite containing no parallelism; a real single run ('天崩地裂日月无光山河变色') reports only 1 and stays under the threshold, so genuine stacking is under-detected too. The heuristic measures run-length, not structural parallelism.

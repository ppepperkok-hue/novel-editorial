# 02 核心目标（Core Goals）

## 目标清单与优先级

### G1【必须】分层编辑部真实且自然地运作

**成功标准**

- 至少 4 个角色（主编 / 责编 / 写手 / 审稿）各司其职，每个角色都有自己层级的判断并留有记录。
- 从“老板下令要一部作品”到一轮成果（方向、大纲或样章）通过，能真实跑通；作者在关键处拍板，且可随时穿透查看任意层的完整记录。
- 协作行为自然发生：不设“必须等待上层批准”的强制关卡；讨论、写作、返工按自然节奏推进；角色能自主发起协作（写手主动问、责编主动退稿、审稿主动提示），不需要作者逐条驱动。

**验收方式**：端到端演示 + 集成测试（无强制关卡检查）+ 用户实际试用反馈。

### G2【必须】作品无 AI 味（硬指标）

**成功标准**

- 质量门可量化：AI 味词表命中率、形容词 / 副词密度、句式重复率、风格一致性评分；默认阈值达标才放行。
- 作者抽样评审：连续 10 个片段，认可“无明显 AI 味”的比例 ≥ 80%。

**验收方式**：质量门测试集 + 作者抽样评审。

**约束**：阈值为默认值，随真实语料迭代校准。

### G3【必须】伙伴是完整的人

**成功标准**

- 每个伙伴有完整档案：身份、性格、价值观、审美倾向、情绪基线、工作习惯、弱点、人际预设、私心。
- 两个伙伴能产生立场分歧并各自坚持（有测试用例验证）。
- 伙伴发言引用自己的记忆与立场；能拒绝违背自己判断的任务，而不是无条件服从。
- 伙伴有属于自己的私有记忆（视角、印象、情绪），与其他伙伴不完全相同。

**验收方式**：档案完整性检查 + 立场分歧测试 + 私有记忆检查 + 记忆留痕检查。

### G4【应该】信息分层与记忆：各层按需取用，向上沉淀，向下分发，可穿透可追溯

**成功标准**

- 写手创作时只拿到写作记忆包（章纲、相关设定、角色状态、风格要求），不灌全量；引用旧设定带来源。
- 决策与事实自动沉淀到对应层级：作品档案（客观事实）、创作日志（过程事实）、伙伴记忆（主观视角）、叙事追踪（伏笔与目标状态）。
- 跨章节连贯：写后续内容时能检索到此前设定；伏笔埋设与回收有追踪。
- 多部作品数据隔离，互不串扰；老板可穿透任意层。

**验收方式**：信息分层集成测试（检查实际注入上下文的内容）+ 跨章节连贯性测试 + 多作品隔离测试。

### G5【可以】开源可用：外部作者拿来能跑

**成功标准**

- 新作者按 README 指引，在干净环境 30 分钟内跑起示例编辑部并产出第一段内容。
- 默认配置开箱即用，无需改代码；文档含快速开始、配置说明、常见问题。

**验收方式**：干净环境按文档走通（fresh setup 测试）+ 外部用户反馈。

## 优先级与取舍

- 资源冲突时按 G1 > G2 > G3 > G4 > G5 取舍。
- G1、G2、G3 是价值主张的直接兑现，属于“必须”；G4 支撑分层的记忆与连贯，属于“应该”；G5 是开源精神的兑现，属于“可以”，不挤占核心开发。
- 开发节奏按阶段迭代，不设大爆炸式一次性交付；每个阶段至少交付一个可验收的协作闭环。

## 反盲从三问

1. 这是需求还是方案？“分层运作、行为自然、无 AI 味、伙伴完整、信息分层”是需求；具体的对话协议、检索算法、质量门公式是方案。
2. 依据是什么？来自用户确认过的核心价值与运作模型：分层是骨架，行为自然发生是魂。
3. 不做会怎样？没有这些目标，项目会退回“全量信息灌入 + 审批式流程”的老路，重蹈前身覆辙。

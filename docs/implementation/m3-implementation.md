## 子阶段 B：可见性基础（U26）

涉及功能 F17 / F18 / F19；单元 U26；依赖 M1 全部。

### B1. 事件流（F17）

- 做什么：
  - 新增 `events` 表（id / workspace_id / type / time / actor / payload），随 Alembic 新增迁移；核心服务在关键节点落事件：对话（agent.message）、草稿产出（draft.created）、质量门通过（quality_gate.passed，payload 带 score）、退稿（review.rejected）、待拍板（decision.requested）。
  - 新增 CLI：`events list <workspace_id> [--type ...] [--limit N]`（按时间倒序回放）、`events watch <workspace_id>`（轮询增量输出，Ctrl+C 退出）。
- 做到什么程度：一轮协作后事件流可按类型与时间回放；watch 能看到新产生的事件。
- 涉及功能：F17；单元 U26-B1。
- 验收标准：端到端测试断言事件类型与顺序（对话 → 草稿 → 质量门 → 待拍板 → 退稿）；watch 增量输出有测试（轮询间隔可配置）；CLI 冒烟。
- 验证方式：pytest + CLI。
- 暂不做：SSE / WebSocket（面板阶段）、跨作品事件聚合、事件过滤分页复杂化。
- 影响评估（涉及基底）：新增表与迁移属于数据库表设计；方案保持 events.py 契约、依赖方向、目录结构不变，仅增量加表与记录点，符合 extension.md 接入流程。备选“从现有表推导事件流”不采用：质量门分数未持久化、decision.requested 无落点，无法如实回放。
- 状态：已完成（62bdf7a 初始实现 + e93acc1 修复，2026-08-14 审查闭合归档）。

### B2. 穿透查询（F18）

- 做什么：新增 `inspect <workspace_id> <关键词>`：跨层检索（作品档案、对话、意见、草稿版本、伙伴笔记、决策、伏笔线索、风格锚点），结果带来源（层名 + 对象 / 角色）；复用 U19 `memory search` 的片段与来源格式，扩展检索范围。
- 做到什么程度：老板一条命令可查任意层记录并看到来源。
- 涉及功能：F18；单元 U26-B2。
- 验收标准：测试断言各层命中带来源；跨作品不串；无命中输出 no matches。
- 验证方式：pytest + CLI。
- 暂不做：全文 / 向量检索、按层权限过滤（老板视角全量）。
- 状态：已完成（0e6ed4e 初始实现 + ceae3a9 修复，2026-08-14 审查闭合归档）。

### B3. 拍板提醒（F19）

- 做什么：
  - 新增 `decision pending <workspace_id>`：列出质量门通过、等待拍板的草稿；无待办时输出空态。
  - 质量门通过时落 `decision.requested` 事件，并在 generate / revise 命令输出末尾提示 awaiting decision（关键节点触发提醒）。
- 做到什么程度：待拍板清单与事件流一致；拍板后从清单消失。
- 涉及功能：F19；单元 U26-B3。
- 验收标准：测试断言 quality passed 后 pending 出现、accept / reject 后消失；事件流含 decision.requested；CLI 冒烟。
- 验证方式：pytest + CLI。
- 暂不做：桌面通知、定时推送、异常提醒规则（返工卡住等，后续再加）。

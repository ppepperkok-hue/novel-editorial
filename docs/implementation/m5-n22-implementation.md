# M5 实施真元文档（无 AI 味深化 · N22 好句识别与保留）

## 总览

- **大阶段**：M7 质量深化扩展线（backlog 见 docs/project-plan/06-new-capability-backlog.md；N8/N9/N19/N20/N21 已收口，N22 为下一 P1 候选）。
- **N22 一句话**：质量门不只挑毛病，也把「出彩的句子」挑出来——去 AI 味时不误伤好句。
- **现状**：
  - F15 `quality.gate`：AI 词 / 修饰词 / 句式重复 / 风格命中四维打分；
  - N8 `quality explain`：逐句三类问题定位 + 改写建议 + 风格一致性摘要；
  - 缺口：explain 只报问题，没有「好句保留」信号；作者照建议整句重写时容易误伤本身出彩的句子。
- **验收总门**：验证四连全绿 + smoke_m3 + stress_m3；至少一条端到端「混合文本（有 AI 味句 + 干净且含具体细节句）→ quality explain 同时输出问题定位与好句区块，好句句号与原文可对应」；既有 993 测试全绿。

## 红线（本阶段强制，06 通用性红线继承）

1. **只报告不代笔**：好句识别只输出标记；不自动改写、不改草稿状态、不落事件、不触发 proactive（继承 06 红线 4）。
2. **不破坏既有语义**：explain 的三类问题定位、渲染与 style 摘要输出全部保持不变；好句区块只新增、不重排既有行。
3. **确定性可复现**：全规则化计算，不调 LLM；同一文本重复运行输出一致。
4. **识别是提示不是判决**：好句判定是「具体细节信号」的规则化提示，作者保留最终判断；好句识别绝不进入质量门分数，不影响通过/失败判定。
5. **体裁自适应**：空文本 / 短文本输出空好句列表，不报错；不依赖任何作品结构。

## 子阶段 S1：好句识别核心服务

### 做什么

- `quality/gems.py`（新模块）：
  - `@dataclass(frozen=True) GoodSentence`：`index`（int，1 起）、`snippet`（str）、`signals`（list[str]，命中的信号标签，去重保序）。
  - `find_good_sentences(text: str) -> list[GoodSentence]`：用 `quality.gate.split_sentences` 分句；每句至少命中一个「具体细节信号」即为好句候选，命中多个信号全部列出；返回按句序排列。
  - **引语片段合并规则**（S1 独立审查 P3 意见）：`split_sentences` 会在引语内的句末标点处切句（如 `「别开灯。」他说。` → `「别开灯` 与 `」他说` 两段）。`find_good_sentences` 须把「前段含开引号且不以闭引号开头、后段以闭引号开头且后段不含开引号」的相邻两段合并为一条好句（前段含开引号即可，兼容 `她说：“别开灯。”然后走了。` 这种前段以说话动词开头的写法）——`index` 取前段、`snippet` 为两段拼接、`signals` 对拼接后的整段重新判定并去重（固定顺序 dialogue → number_detail → sensory；片段内句末标点沿用既有分句口径不保留），保证句号与 quality explain 一致。
  - **闭引号残句跳过规则**（S2 独立审查 P2 意见）：无法满足合并条件、且以闭引号开头的片段（含单独一个闭引号）不是句子，直接跳过、绝不出现在好句列表中；输出不出现以闭引号开头的残句。
  - 信号常量与判定（全部确定性字符串匹配，常量集中定义并文档化）：
    1. `dialogue`（对话引语）：句子含 `「」『』“”‘’` 任一引号字符；
    2. `number_detail`（数字细节）：句子含「数字 + 单位」组合——数字支持阿拉伯数字与中文数字（零一二三四五六七八九十百千两），单位限 `点时分年月日岁号秒米里斤两钱块元`（本地正则，不复用 consistency 私有函数）；
    3. `sensory`（感官细节）：句子含 `SENSORY_DETAIL_WORDS` 中任一单字（常量约 24 个：光影声味汗血锈霜雪雨风烟尘灰铁灯钟门窗锁刀火水石；注明是「起点不是判决」的提示性信号）。
  - **不依赖质量门分数**：AI 味句若含信号同样可被标为好句——这正是「不误伤」的核心，explain 里问题与好句可同时出现。
- tests（`tests/test_quality_gems.py`）：三类信号各命中、多信号合并、AI 味句与好句并存、无信号文本返回空、空文本、确定性、边界（数字单位组合、引号判定）。

### 做到什么程度

- 好句识别可复现；CLI 不接。

### 验收标准

- 单测覆盖上述全部路径；边界正确。

### 验证方式

pytest + ruff + pyright + 宪法校验。

### 暂不做

- CLI 集成（S2）、文档（S3）、独立 `quality gems` 命令、好句入库 / 收藏（N15 联动）、LLM 语义级好句判断、好句进入质量门分数。

## 子阶段 S2：quality explain 集成与端到端

### 做什么

- `cli/quality.py` 的 `quality explain` 在既有输出末尾追加好句区块（style 摘要之后）：
  ```text
  good sentences: 句 2、5（对话引语、数字细节、感官细节，建议保留）
    2: 她把钥匙放进铁盒，锈声在雨里很轻。
    5: 「别开灯」他说。
  ```
  - 摘要行的信号标签按信号名中文映射（dialogue→对话引语、number_detail→数字细节、sensory→感官细节），按句子去重后以顿号连接；
  - 逐句行缩进 2 空格，`句号: 原文`；
  - 引语内含句末标点时（如 `「别开灯。」他说。`），好句条目按 S1 合并规则显示为一条（`句 5: 「别开灯」他说`）；
  - 无好句时不输出该区块；空文本 / 短文本同样不输出且不报错。
- **既有输出完全不变**：问题行、CLEAN_MESSAGE、style 摘要的行序与文案保持原样，好句区块只追加在末尾。
- tests：
  - `tests/test_quality_gems.py` 或既有 `tests/test_quality_explain.py` 追加 CLI 端到端——混合文本（AI 味句 + 含信号好句）→ 问题定位与好句区块同时出现、句号可对应；
  - 干净含细节文本 → 只有好句区块、无问题；
  - 无信号文本 → 无好句区块；
  - 既有 explain 断言全部不回退（三类问题、style 摘要、CLEAN_MESSAGE 顺序）。

### 做到什么程度

- 作者在 quality explain 里同时看到「哪里有问题」和「哪些句子值得保留」，去 AI 味不再是盲目整句重写。

### 验收标准

- 端到端用例 + 边界；既有 explain 测试零回归；smoke_m3 仍 SMOKE OK；stress_m3 无回归。

### 验证方式

pytest（新增用例）+ smoke_m3 + stress_m3 + ruff + pyright + 宪法。

### 暂不做

- 独立 `quality gems` 命令、好句收藏 / 入库（N15 另拆）、面板展示（N12）。

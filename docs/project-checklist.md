# 立项清单（Project Checklist）

## 一句话价值

让一个人也能拥有一间真正分层运作的文学编辑部：作者是老板，一群有完整人格、有判断、有记忆的 AI 伙伴各司其职，通过自然协作，把各类文学创作一步步磨成真正想写的样子。

## 核心目标（G1–G5）

1. **G1【必须】** 分层编辑部真实且自然地运作：分层是骨架，行为自然发生是魂，无强制关卡，老板可穿透。
2. **G2【必须】** 作品无 AI 味：可量化质量门，抽样认可率 ≥ 80%。
3. **G3【必须】** 伙伴是完整的人：有档案、会分歧、会拒绝、有私有记忆。
4. **G4【应该】** 信息分层与记忆：按需取用、向上沉淀、向下分发、可穿透可追溯、多作品隔离。
5. **G5【可以】** 开源可用：干净环境 30 分钟跑通示例。

详见 [03-core-goals.md](project-plan/03-core-goals.md)。

## 核心架构

- 运作模型：组织分层（老板 → 主编 → 责编 → 写手 / 审稿）、判断分层、信息分层。详见 [02-editorial-operation-model.md](project-plan/02-editorial-operation-model.md)。
- 核心价值与边界：见 [01-core-value.md](project-plan/01-core-value.md)。

## 功能范围

- 首批功能 F1–F21（组织层 / 协作层 / 信息层 / 质量层 / 可见性 / 开源层）。详见 [04-feature-breakdown.md](project-plan/04-feature-breakdown.md)。
- 明确不做：自动发布、图形面板（后置）、多作者共编、一键完结、成本中心、外部知识库自动导入。

## 里程碑

- **M1** 最小可验证版本：一轮自然协作闭环（讨论 → 写作 → 质量门 → 拍板），15 个单元。**已完成（2026-08-13）**。
- **M2** 伙伴完整与信息分层深化（8 个单元）。
- **M3** 开源与可见性（4 个单元，图形面板后置）。

详见 [05-executable-units.md](project-plan/05-executable-units.md)。

## 全局约束与风险

- **上下文成本**：信息分层是控制成本的关键；分层不当会造成信息缺失，用“按需取用 + 来源可溯 + 老板可穿透”兜底。
- **去 AI 味标准**：没有绝对标准，先立默认阈值，随真实语料迭代校准。
- **LLM 依赖**：统一客户端先行，支持真实 key 与模拟模式，错误路径先测。
- **开源可用**：默认配置开箱即用，文档与示例完整。
- **节奏**：用户明确慢慢来，按阶段迭代，不设大爆炸式交付。

## 决策记录

- **为什么重写**：前身 n8n 流水线逻辑与用户真正想要的创作协作不符，试用后判定推倒重来；归档版可回退。
- **为什么是分层**：从真实编辑部运作推导，组织、判断、信息三层叠合；分层是骨架，不是审批流。
- **为什么 CLI / API 先行**：核心是创作与协作本身，面板只是窗户；可见性机制先行，图形面板后置。
- **为什么不做自动发布**：发布不是创作协作的核心，砍掉以聚焦主线。
- **为什么慢慢来**：用户要求，且避免重蹈“大而全却逻辑错位”的覆辙。

## 验收门（Phase 0 完成条件）

- 反盲从三问全有答案（需求与方案分清、依据可查、不做有后果）。
- 价值一句话可讲清，目标全部可测量、可验收，功能与目标一一对应。
- 每个功能都有可独立验收的单元，无黑盒功能；M1 里程碑可落地。
- 本清单经用户确认后，进入选技术栈。

## 番茄发书流程（已实测）

1. 作者实名认证（账号后台完成）。
2. 建书：`POST /api/author/book/create/v0/`（每天限 1 本；作品信息审核通过后才能发章节）。
3. 每章三步：
   - `POST /api/author/article/new_article/v0/` → 返回 `item_id` + `volume_id`
   - `POST /api/author/article/cover_article/v0/` → 保存标题和正文（草稿）
   - `POST /api/author/publish_article/v0/` → 提交审核

规则：

- 标题必须形如「第 1 章 标题」（5-30 字），不带序号会报 `-3007 标题长度不符合规范`
- 正文至少 1000 字（推荐 2000-2200），不足报 `-2 章节字数不足`
- 大段重复内容报 `-3026`
- 查询接口：`chapter_list/v1`（已发布）、`draft_list/v1`（草稿）、`book_list/v0`（`chapter_number` 是下一个章节号）

## 工作流结构

每日触发(08:00) → 备份数据库 → 设定题材 → 查章节号(book_list) → 算章节号 → Planner出大纲 → 解析大纲(规范化章纲)

├─ 守护细纲 → 解析守护(世界观约束)
│
├─ 写手A → 润色A → 审稿A → 读者审稿A → 质量门A(≥1500字且 双审 passed) → 提炼剧情A → 整理剧情A → 排版A → 新建草稿A → 解析草稿A → 保存内容A → 提交发布A → 校验发布A

└─ 写手B → 润色B → 审稿B → 读者审稿B → 质量门B(≥1500字且 双审 passed) → 提炼剧情B → 整理剧情B → 排版B → 新建草稿B → 解析草稿B → 保存内容B → 提交发布B → 校验发布B

→ 完成

失败容错：质量门/校验发布不再抛错，失败分支在排版处短路，另一章照常发布；
失败原因写入数据库 `chapters[].error`，次日可人工补发。

## 作品资料自动链路（2026-08-09 新增）

每天运行时自动做四件事：

1. `查章节号`：读 `book_list` 拿最新章节号与书名/简介状态
2. `生成作品资料`：DeepSeek 生成书名、简介、标签、主角名与卷目标（会沿用数据库里已有主角与书名，保持连续）
3. `提交作品资料`：仅当书还是默认名（「用户……的新书」）或简介过短时，调 `/api/author/book/modify_book/v0/` 写入番茄后台
4. `记录作品资料`：运行结果（书名/简介/标签/主角/大纲/章节）写入 `demo.db`，供前端作品库展示

作品资料生成节点在 n8n 画布里位于「算章节号」之后、Planner 之前；章节号从 `chapter_number+1` 开始，A=第 N 章、B=第 N+1 章。

## 已知限制

- 番茄每日提交字数有上限（实测约 9000+ 字后报 `-1019 提交字数超出每日上限`）；日更两章（约 4400 字）安全，测试日连续多次运行会触发
- 每天最多创建 1 本新书，作品信息需过审后才能发章节

## 连贯性系统（2026-08-10 重写）

参考 GitHub 上的 AI 长篇项目（OpenNovel、long-novel-writer、AI Fiction Studio 等）后，把流水线升级为「故事圣经 + 章纲蓝图 + 记忆包」模式：

1. **故事圣经**：书名、简介、风格指南、7+ 角色（人设/成长弧/说话习惯）、9+ 世界设定、主线骨架、第一卷目标、金手指规则——生成一次后冻结在数据库
2. **章纲蓝图**：提前规划 10 章（标题/大纲/场景/角色/情感/钩子类型），每章标题全书唯一
3. **记忆包**：每章写作前自动组装「上一章结尾原文 + 最近章节摘要 + 角色当前状态 + 活跃伏笔 + 已有标题」，写入写手/审稿提示词
4. **写后沉淀**：每章发布后自动提取结构化摘要、角色状态变化、事件与伏笔，写回数据库供下一章使用
5. **审稿强化**：新增连贯性专审（上一章结尾 vs 本章开头逐句对比、角色 OOC、设定吃书、标题重复、AI 痕迹），score≥7 且无 critical 才放行

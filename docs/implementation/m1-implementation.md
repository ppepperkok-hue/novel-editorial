# M1 实施真元文档（Single Source of Truth）

## 总览

- **大阶段**：M1 最小可验证版本——一轮“带着自然行为”的协作闭环：老板下令 → 编辑部讨论（至少一次角色自主发起）→ 写手产出样章 → 质量门 → 老板拍板；全程有日志，多作品隔离。
- **依赖顺序**：按 backlog 依赖列重排，编号不是实现顺序。
- **基底（不可随意翻）**：技术栈、src 目录结构、数据库表设计（Alembic）、核心事件契约、错误码枚举、依赖方向。
- **验收总门**：验证四连全绿（pytest / ruff / pyright / CLI 冒烟）；无越界实现（不偷做、不多做）；每子阶段完成即停，回报三问（对照文档做完哪些、改了哪些地方、怎么验证）。

## 子阶段 A：地基收尾（U1–U4）

当前骨架已具备 init / health / version / works create / list / show 与默认班子；本阶段补齐 U1–U4 的验收缺口。

### A1. init 幂等与配置模板

- 做什么：`init` 可重复执行（已存在目录/配置时输出提示且不报错）；`.env.example` 与 `config.example.toml` 已在仓库；init 生成 `config.toml` 时注明来源模板。
- 做到什么程度：重复执行 `init` 两次，第二次仍成功。
- 涉及功能：F1；单元 U1。
- 验收标准：CLI 冒烟 + 测试（同一数据目录 init 两次）。
- 验证方式：pytest 测试 + 手动冒烟。
- 暂不做：配置文件热加载、多配置文件合并。

### A2. 伙伴简档可查看

- 做什么：新增 `agents show <workspace_id>`（或 `works show` 扩展），展示每个伙伴的名字、职位、性格要点、立场偏好；为默认班子补齐有意义的简档内容（personality / stance 不再是空字符串）。
- 做到什么程度：CLI 一条命令看到全部四人完整简档字段。
- 涉及功能：F3；单元 U4。
- 验收标准：测试断言默认班子四人字段齐全且非空；CLI 输出包含字段。
- 验证方式：pytest + CLI 冒烟。
- 暂不做：简档编辑（M2 U16）、简档个性化配置命令。

## 子阶段 B：LLM 客户端与自然对话（U5–U6）

### B1. 真实 LLM 客户端

- 做什么：实现真实客户端（OpenAI 兼容协议，默认 DeepSeek base_url），支持超时与错误映射（超时/鉴权/限流 → NovelError + LLM_ERROR）；保留 MockLLMClient；`build_client` 按有无 key 选择。
- 做到什么程度：有 key 时能完成一次真实调用；无 key 时走 mock；错误路径有测试。
- 涉及功能：U5。
- 验收标准：mock 模式测试通过；真实调用用模拟服务器或真实 key 冒烟（无 key 环境则标记为 CI 跳过项，本地有 key 才跑）。
- 验证方式：pytest（httpx MockTransport 或 mock 客户端）+ 本地冒烟。
- 暂不做：流式输出、多模型路由、重试策略（错误路径先测）。
- 依赖：新增 `openai` 依赖（官方 SDK，OpenAI 兼容）。

### B2. 对话事件与消息存储

- 做什么：作品库新增 `messages` 表（id / workspace_id / role / actor / content / created_at），复用事件契约；写一条消息即落一条记录。
- 做到什么程度：对话记录可入库、可查询。
- 涉及功能：F4、F10 基础；单元 U6、U11 基础。
- 验收标准：消息落库测试；`events.py` 的 Event 结构与消息记录对应。
- 验证方式：pytest。
- 暂不做：创作日志完整版（U11 在子阶段 E）、SSE。

### B3. talk 命令：自然对话与自主发起

- 做什么：新增 `talk <workspace_id>` 交互（或 `talk send` 单次命令）：作者发言 → 指定角色回复；`@写手` 路由到写手；全员讨论轮次；至少一次由角色主动发起话题（如责编主动提问），无需作者点名；对话记录入库。
- 做到什么程度：CLI 可完成一轮作者→角色→自主发起的对话。
- 涉及功能：F4；单元 U6。
- 验收标准：测试断言对话记录完整、自主发起行为可识别（payload 标记 initiator=agent）；CLI 冒烟。
- 验证方式：pytest + CLI 冒烟。
- 暂不做：对话流式展示、多轮记忆（M2）、会议引擎。

## 子阶段 C：风格锚点、记忆包、草稿（U12、U7、U8）

### C1. 风格锚点

- 做什么：作品级风格说明与禁忌词配置：`style set <workspace_id> --description ... --forbidden ...`，存作品库；写手记忆包与质量门可读取。
- 做到什么程度：配置生效、可查看。
- 涉及功能：F14；单元 U12。
- 验收标准：测试断言配置落库并可读；CLI 冒烟。
- 验证方式：pytest + CLI。
- 暂不做：风格样例解析、风格一致性评分（U21）。

### C2. 写作记忆包

- 做什么：写手写作前组装记忆包：作品档案片段（简版：标题/体裁/描述）、风格锚点、章纲占位（无章纲时为空）；记忆包内容可查看（`memory pack <workspace_id>`）；不含无关作品数据。
- 做到什么程度：`draft generate` 时注入记忆包，内容可配置。
- 涉及功能：F8 基础、F14；单元 U7。
- 验收标准：测试断言记忆包包含且仅包含本作品数据；跨作品不串。
- 验证方式：pytest。
- 暂不做：按需检索与来源引用（U19）、多表记忆聚合。

### C3. 草稿产出与版本

- 做什么：新增 `draft generate <workspace_id>`（写手产出，走 LLM mock/真实 + 记忆包）、`draft list`、`draft show <id>`、`draft diff <id> <v1> <v2>`；草稿表与版本表（drafts / draft_versions），产出即存版本 v1，再次产出 v2。
- 做到什么程度：两次产出生成两个版本，可对比差异。
- 涉及功能：F5；单元 U8。
- 验收标准：测试断言版本递增、diff 可用；CLI 冒烟。
- 验证方式：pytest + CLI。
- 暂不做：并行草稿、自动回退合并。

## 子阶段 D：反馈返工与拍板（U9–U10）

### D1. 意见与返工

- 做什么：`review add <draft_id> --from <agent|author> --content ...` 提意见；`draft revise <draft_id>` 指定修改人重产出新版本并保留理由；至少一次责编主动退稿、写手反驳后再修改（日志可识别双方立场）。
- 做到什么程度：意见入库、版本 +1、理由可查。
- 涉及功能：F6；单元 U9。
- 验收标准：测试断言完整链路（提意见→反驳→修改→理由留痕）；自然行为种子验收。
- 验证方式：pytest + CLI。
- 暂不做：意见评分、自动派单。

### D2. 作者拍板

- 做什么：`decision accept <draft_id>` / `reject` / `note`；状态流转：draft → accepted / rejected，reject 后允许再次 revise；记录决策人（作者）。
- 做到什么程度：命令状态流转正确、可查询。
- 涉及功能：F7 基础；单元 U10。
- 验收标准：测试断言三种命令状态流转与记录。
- 验证方式：pytest + CLI。
- 暂不做：多级审批（分层不设关卡）、穿透查看完整版（U26）。

## 子阶段 E：创作日志与质量门（U11、U13）

### E1. 创作日志

- 做什么：对话、决策、版本、意见、退稿理由自动记录（复用事件契约入库）；`log <workspace_id>` 可逐步回溯一轮完整流程。
- 做到什么程度：一轮闭环后日志完整可查。
- 涉及功能：F10；单元 U11。
- 验收标准：端到端测试一轮流程后逐步回溯日志。
- 验证方式：pytest + CLI。
- 暂不做：日志查询过滤分页、审计导出。

### E2. AI 味质量门基础

- 做什么：实现基础检测：AI 味词表命中率、形容词/副词密度；输出报告（score / details / passed）；超阈值拦截（draft 标记 quality_failed）；默认阈值进配置。
- 做到什么程度：测试集（明显 AI 味 vs 正常段落）判定达标；拦截生效。
- 涉及功能：F15；单元 U13。
- 验收标准：测试集通过率 ≥ 90%（明显/正常各至少 10 例）；拦截后草稿不可 accept。
- 验证方式：pytest。
- 暂不做：句式重复、风格一致性（U21）、定位与改写建议（U22）。

## 子阶段 F：隔离与端到端（U14–U15）

### F1. 作品隔离验证

- 做什么：测试两部作品互查不到对方数据（消息、草稿、风格、简档）；数据层与 CLI 双路径验证。
- 做到什么程度：隔离测试通过。
- 涉及功能：F13；单元 U14。
- 验收标准：pytest 隔离测试（跨作品查询为空/报错）。
- 验证方式：pytest。
- 暂不做：多作品管理的图形界面。

### F2. demo 端到端

- 做什么：`demo` 命令一条跑通：建作品 → 讨论（含自主发起）→ 生成样章 → 质量门 → 拍板，全程日志落库，输出可读记录；默认 mock LLM。
- 做到什么程度：M1 闭环可一键演示。
- 涉及功能：F1–F15 汇总；单元 U15。
- 验收标准：demo 命令完整跑通；日志中可识别“谁先动”；验证四连全绿。
- 验证方式：CLI 冒烟 + pytest 集成测试。
- 暂不做：真实 key 端到端（本地可选）、可见性三扇窗（M3）。

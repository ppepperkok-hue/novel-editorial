# 03 功能拆解（Feature Breakdown）

从核心架构（运作模型 + 核心目标）长出第一版功能清单；后续功能继续往骨架上挂。

优先级：P0 必须 / P1 应该 / P2 可以。每个功能标注所属目标。

## 功能清单

### 组织层（班子与角色）

### F1【P0 / G1】作品工作区

作为作者，我想要为一部作品建立独立的工作区（标题、体裁、简介），以便围绕它组建编辑部和开展协作。

前置：无。

### F2【P0 / G1】伙伴班子配置

作为作者，我想为作品配置参与协作的伙伴（默认主编 / 责编 / 写手 / 审稿），以便按作品需要组建班子。

前置：F1。

### F3【P0 / G3】伙伴档案

作为作者，我想为每个伙伴建立和编辑完整档案（身份 / 性格 / 价值观 / 审美 / 情绪基线 / 工作习惯 / 弱点 / 人际预设 / 私心），以便他们是有来历、有立场的人。

前置：F1。

### 协作层（行为自然发生）

### F4【P0 / G1】自然对话协作

作为作者，我想在作品里与伙伴们自由对话、@指定伙伴或全员参与，伙伴也能主动发起话题，以便协作按自然节奏发生。

前置：F2、F3。

### F5【P0 / G1】草稿与版本

作为作者，我想看到伙伴产出的草稿及其版本历史，以便随时对比和回退。

前置：F4。

### F6【P0 / G1】反馈与返工

作为作者，我想对草稿提意见、指定伙伴修改、保留修改原因；责编能退稿、写手能反驳，以便作品被真正磨过。

前置：F4、F5。

### F7【P0 / G1】作者介入与穿透

作为作者，我想随时接受、拒绝、给指示，并能查看任意层的完整记录，以便我作为老板真正拥有最终决定权。

前置：F4、F10。

### 信息层（记忆与分层）

### F8【P0 / G4】分层视图与按需检索

作为各层角色，我想默认只看到自己判断所需的最小充分信息，需要时按需检索并带来源引用，以便信息不淹没判断、成本可控。

前置：F9、F10、F11、F12、F13。

### F9【P0 / G4】作品档案

作为作者和伙伴，我想让设定、角色、关系、时间线等客观事实由确认与创作沉淀下来、来源可溯，以便成为作品的共同底座。

前置：F1。

### F10【P0 / G4】创作日志

作为作者，我想让对话、决策、版本、意见、退稿理由自动记录，以便“当时为什么这么定”永远查得到。

前置：F4。

### F11【P0 / G3】伙伴私有记忆

作为伙伴，我想有自己的笔记、印象和情绪记录，允许与其他伙伴不同，以便我是有自己视角的人。

前置：F3。

### F12【P1 / G4】叙事追踪

作为作者和审稿，我想记录伏笔的埋设与回收、角色目标状态、悬置的钩子，以便长线叙事有据可查。

前置：F9。

### F13【P0 / G4】作品隔离

作为作者，我想让多部作品的数据互不串扰，以便同时管理多个编辑部。

前置：F1。

### 质量层（去 AI 味）

### F14【P0 / G2】风格锚点

作为作者，我想为作品定义风格基准（风格样例、禁忌词、偏好），以便写作与检测都对照同一个标准。

前置：F1。

### F15【P0 / G2】AI 味质量门

作为作者，我想在产出通过前看到可量化的 AI 味检测报告（词表命中 / 密度 / 句式重复 / 风格一致性），以便守住无 AI 味这条线。

前置：F14。

### F16【P1 / G2】AI 味定位与改写建议

作为作者，我想知道 AI 味具体在哪些位置、怎么改，以便快速返工。

前置：F15。

### 可见性（老板视图）

老板“看见编辑部工作”的三扇窗。机制先行：CLI 阶段提供基础形态（实时事件流、穿透查询、拍板提醒）；完整呈现随图形面板阶段落地。

### F17【P1 / G1】实时观察流

作为作者，我想在协作发生时实时看到事件流（谁在发言、谁在写、谁退了谁的稿），以便像在编辑部里走过一样掌握动静。

前置：F4、F10。

### F18【P1 / G1】穿透查看

作为作者，我想随时查看任意层的完整记录（写手记忆包、责编跟稿依据、审稿检查清单、版本对比、退稿理由），以便理解他们为什么这么判断。

前置：F7、F8、F10。

### F19【P1 / G1】关键节点提醒

作为作者，我想在需要拍板或出现异常时被主动提醒（样章完成、返工卡住、方向要定），以便只在关键处出现。

前置：F4、F6、F10。

### 开源层（拿来能跑）

### F20【P2 / G5】快速开始与示例

作为新作者，我想按 README 在干净环境 30 分钟内跑起示例编辑部并产出第一段内容，以便开箱即用。

前置：核心功能可用。

### F21【P2 / G5】配置与常见问题文档

作为新作者，我想看到配置说明和常见问题，以便不依赖作者本人解释。

前置：F20。

## 做 / 不做清单

**做**：上表 F1–F21（首批从 P0 开始，P1/P2 后续挂载）。

**不做**：

- 自动发布到外部平台（番茄、起点等）。
- 图形前端面板与桌面应用（后置；先行 CLI / API 交互）。
- 多作者实时共编。
- 一键从想法到完结的全自动流水线。
- 成本核算中心 / 预算仪表盘。
- 外部知识库自动导入（后置）。

## 依赖关系

- 基础层：F1 → F2 / F3 / F9 / F13 / F14
- 组织层：F2、F3 → F4
- 协作层：F4 → F5 → F6；F4 → F7
- 信息层：F9 / F10 / F11 / F12 → F8（检索来源）；F10 → F7（穿透查看）
- 质量层：F14 → F15 → F16
- 可见性：F4 / F10 → F17；F7 / F8 / F10 → F18；F4 / F6 / F10 → F19
- 开源层：核心功能可用 → F20 → F21

无循环依赖。

## 后置候选（M4 三个工程瓶颈完成后统一规划）

以下候选先记录在案，不纳入当前实施；待三个瓶颈（CLI 拆包 / 检索性能 / 测试分片）收口后，连同自然行为与自由意志开发一起做阶段规划，再分阶段立项。

- 向量检索 / 语义记忆：以"意思相近"补充子串命中，作为知识库联想新能力立项（M4-ENG-2 文档已评估：查询毫秒级，但增量写入依赖外部嵌入、破坏本地写库原子性，属架构级增量，不适合解性能瓶颈）。
- 自然行为 / 自由意志：允许行为自然发生的最小限度分层流程（M1 阶段已定架构基调），下一阶段正式立项。
- 其余候选（记忆检索增强、跨作品聚合、面板三扇窗细化等）：规划时统一收编，按优先级挂载。

## 反盲从三问

1. 这是需求还是方案？“自然对话、草稿版本、分层记忆、质量门、伙伴档案”是功能需求；“对话协议”“检索算法”“检测公式”是方案。
2. 依据是什么？每个功能都能回溯到 G1–G5 目标与分层运作模型；挂不上的功能一律不进首批。
3. 不做会怎样？砍掉的都是非核心（发布 / 面板 / 共编 / 一键完结 / 成本中心），不影响“分层运作 + 自然协作”主线。

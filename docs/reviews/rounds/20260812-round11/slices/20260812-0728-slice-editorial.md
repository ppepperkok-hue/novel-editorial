Full review comments:

- [P1] Publish gate-bypass: rework failure returns original passed gate with failed rewrite text — E:/code/novel-editorial/tools/editorial_daily.py:1160-1160
  tools/editorial_daily.py:1160 (`return gate, editor_text, current_review` in `_review_retry`) returns the ORIGINAL gate together with the LAST retried `editor_text` when retries are exhausted. In the rework branch of `_run_track` (tools/editorial_daily.py:1272-1282) this runs even when the gate already passed, so a chapter whose rewrite repeatedly fails `quality_gate` is published under the stale pass, and `_settle_rework(conn, track_req, ok=bool(gate.get("passed")))` marks the action done and resolves the message as `rework` — i.e. the failed rewrite is shipped and the loop is reported closed. Reproduced with `REVIEW_RETRY_MAX=1`, a passed gate plus `extra_reason` rework: `_review_retry` returned `gate.passed=True` with the failing rewrite text. The exhaust path should return the original `editor_text` (the only text that actually passed) and settle the rework as pending, as `test_review_retry.py::test_retry_exhausts_and_keeps_original_gate` implicitly expects (its mock makes original and retried text identical, so it cannot catch this).

- [P2] Workday active-run guard bypassed by org/meeting modes, allowing two concurrent workdays — E:/code/novel-editorial/tools/workday.py:110-121
  tools/workday.py:110-121 only treats `source='workday' AND status='running'` as an active workday, but the non-produce branch at tools/workday.py:179 flips the row to `status='skipped'` while the workday is still open (`phase='awaiting_close'`, set at line 182). Reproduced: `workday.open(mode='org')` leaves a row `{phase:'awaiting_close', status:'skipped'}`, and a second `workday.open(mode='write')` passes the guard and creates a second workday, so two open workdays coexist with double broadcasts, duplicate diaries and a second full LLM produce chain. The guard should consider any non-finished workday (e.g. `phase != 'finished'`), not only `status='running'`; this is the same invariant previously patched for running workdays (see docs/reviews/20260811-persona-blood-review.md).

- [P3] Global (novel_id=0) messages are injected but never marked read — E:/code/novel-editorial/tools/editorial_daily.py:218-235
  `agent_context.build_context_snapshot` (tools/agent_context.py:33-45) queries the mailbox with `ref_novel_id IN (0, novel_id)`, so global-scope messages are shown as `未读`. But `_mark_injected_read` (tools/editorial_daily.py:218-235) marks read only via `mailroom.list_messages(novel_id=ctx.novel_id)`, which filters `ref_novel_id=?` exactly; when `novel_id > 0` any unread message with `ref_novel_id=0` (e.g. an agency `post_issue` sent before a book existed) is injected into every snapshot and never transitions to read, keeping the unread badge and `unread_summary` inflated forever. Use the same scope set `IN (0, novel_id)` when collecting the ids to mark.

- [P3] 'completed_with_pending' status renders as idle in exported flow report — E:/code/novel-editorial/tools/export_flow_html.py:71-88
  `workday.close` persists `status='completed_with_pending'` (tools/workday.py:306), but neither status map in `export_flow_html.render_html` (tools/export_flow_html.py:71-88) nor the fallback in `flow_graph.build_flow` recognizes it: `status_text` falls through to `待命（暂无运行）` and `status_class` to `idle`, so a fully completed workday with pending follow-ups is exported/marked as never-run in the panel view. Add `completed_with_pending` to both maps (and to `daily_runs.local_executions`' `completed -> success` mapping for consistency).

- [P3] CLI topic/planning meetings run with weekly agenda labels in prompts — E:/code/novel-editorial/tools/agent_meeting.py:618-621
  In `agent_meeting.main()` the calls at tools/agent_meeting.py:618 (`chair_pick(...)`) and :645 (`round_speech(...)`) omit the `kind` argument, so both default to `kind='weekly'` (definitions at lines 311 and 358-359). A `--kind topic` or `--kind planning` CLI meeting is therefore introduced to the chair as `本次会议类型：编辑部例会` and each speaker is told to start with `本周小结` instead of the topic/planning agenda label, degrading prompt accuracy. Pass `args.kind` through to both calls.

- [P3] Workday stuck forever when process dies during 'opening' phase — E:/code/novel-editorial/tools/workday.py:239-239
  `open()` inserts the workday row with `phase='opening'` (tools/workday.py:137) and only advances it after `_morning_plan` (which for `mode='free'`/boss-instruction includes a long LLM call). If the process is killed in that window, `resume()` refuses the phase (tools/workday.py:208) and `close()` refuses it too (tools/workday.py:239), while `open()` keeps rejecting a new workday because the row is still `status='running'` (tools/workday.py:110-121). Recovery exists only via `daily_runs.recover_stale_runs` at web_api startup (12h threshold), so CLI-only users are locked out. Allow `close()`/`resume()` from `opening`/`morning`, or have `open()` treat stale non-finished rows as closed.

- [P3] Dead code: compress_history is never called — E:/code/novel-editorial/tools/agent_meeting.py:280-280
  `compress_history` (tools/agent_meeting.py:280-310) is defined but has no callers — `round_speech` still receives `compressed_history=""` everywhere and `main()` never invokes it. Either wire it into the round loop (the docstring says it exists to prevent long raw histories from pushing models into empty-content loops) or remove it to avoid drift between the implemented and the intended meeting flow.

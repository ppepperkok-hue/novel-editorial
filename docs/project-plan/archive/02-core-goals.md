# 02 核心目标（Core Goals）

## 目标清单与优先级

### G1【必须】自然的创作协作闭环：作者与 AI 伙伴围绕一部作品的一轮协作能真实跑通

**成功标准**

- 作者与至少 3 个 AI 伙伴（如主编 / 责编 / 写手 / 审稿，各有角色）能以自然对话方式协作：提出想法 → 讨论 → 产出草稿 → 反馈 → 修改 → 通过。
- 作者介入自然：随时说话、拒绝、给指示，不依赖固定表单或审批节点。
- 协作全程有记录（对话、产出版本、修改原因），可回溯。

**验收方式**：端到端演示 + 集成测试 + 记录完整性检查。

### G2【必须】产出无 AI 味（硬指标）

**成功标准**

- 质量门含可量化检测：AI 味词表命中率、形容词 / 副词密度、句式重复率、风格一致性评分；默认阈值达标才放行。
- 作者抽样评审：连续 10 个片段（或 10 章），认可“无明显 AI 味”的比例 ≥ 80%。

**验收方式**：质量门测试集 + 作者抽样评审。

**约束**：阈值为默认值，随真实语料迭代校准，不追求一次性完美。

### G3【必须】AI 伙伴是完整的人

**成功标准**

- 每个伙伴有完整档案：身份、性格、价值观、审美倾向、情绪基线、工作习惯、弱点、人际预设、私心。
- 两个伙伴能产生立场分歧并各自坚持（有测试用例验证）。
- 伙伴发言会引用自己的记忆与立场；能拒绝违背自己判断的任务，而不是无条件服从。

**验收方式**：档案完整性检查 + 立场分歧测试 + 记忆留痕检查。

### G4【应该】记得住：设定、关系、伏笔跨章节不丢

**成功标准**

- 设定、角色状态、伏笔、时间线统一沉淀并全员共享；创作时自动引用相关旧设定。
- 连续性测试：写后续内容时能检索到此前设定；伏笔的埋设与回收有追踪。
- 多部作品数据隔离，互不串扰。

**验收方式**：跨章节连贯性集成测试 + 多作品隔离测试。

### G5【可以】开源可用：外部作者拿来能跑

**成功标准**

- 新作者按 README 指引，在干净环境 30 分钟内跑起示例编辑部并产出第一段内容。
- 默认配置开箱即用，无需改代码；文档含快速开始、配置说明、常见问题。

**验收方式**：干净环境按文档走通（fresh setup 测试）+ 外部用户反馈。

## 优先级与取舍

- 资源冲突时按 G1 > G2 > G3 > G4 > G5 取舍。
- G1、G2、G3 是价值主张的直接兑现，属于“必须”；G4 支撑跨章节体验，属于“应该”；G5 是开源精神的兑现，属于“可以”，不挤占核心开发。
- 开发节奏按阶段迭代，不设大爆炸式一次性交付；每个阶段至少交付一个可验收的协作闭环。

## 反盲从三问

1. 这是需求还是方案？“能自然协作、无 AI 味、伙伴完整”是需求；具体的对话格式、检测算法是方案。
2. 依据是什么？来自用户确认过的核心价值：创作与协作本身是核心、AI 味是红线、伙伴完整度要高。
3. 不做会怎样？没有可测量目标，项目会回到“功能堆砌、无法判断成功”的老路——这正是前身的教训。

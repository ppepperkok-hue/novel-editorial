## 红线（本阶段强制，06 通用性红线继承）

1. **只报告不代笔（红线 4 继承）**：影响分析只输出「哪些层、哪些条目、为什么命中」，绝不自动改写正文、不绕过角色判断。
2. **不阻塞（红线 1/2 继承）**：impact 是纯只读检索命令，不构成任何创作前置；检索失败只告警，不影响既有命令。
3. **口径与检索层一致**：命中判定沿用关键词子串（设定名称 + 内容折叠片段），与 memory search / inspect 口径可解释；不引入新检索语义。
4. **来源可溯**：每条影响带层标签与来源引用，与既有 [档案]/[对话]/[意见]/[版本]/[笔记]/[线索]/[设定] 输出风格一致。

## 子阶段 L1：影响分析核心服务

### 做什么

- `core/impact.py`（新模块）：
  - `analyze_setting_impact(db, workspace_id, setting_id, limit=20) -> SettingImpactReport`：
    - 取设定（NOT_FOUND 语义与 setting.get_setting 一致）；
    - 关键词集 = 设定名称（整体子串）+ 内容折叠（" ".join(content.split())）中提取的稳定片段（≥2 字、去重、按出现频次取前 N，避免整段长内容当关键词）；
    - 跨层检索：版本正文（DraftVersion）、对话（Message）、意见（Review）、伏笔线索（PlotThread）、伙伴笔记（AgentMemory 活跃）、设定（其他条目名/内容）——任一关键词子串命中即计入（大小写不敏感）；
    - 排除自身条目与自身历史版本；每条影响 = 层标签 + 来源引用（如「第X章 vN」「写手私记」）+ 命中片段（折叠截断 60 字）；
    - 按层固定顺序（版本 → 对话 → 意见 → 线索 → 笔记 → 设定）排序，层内按更新时间/创建时间倒序；limit 截断，报告带 total；
  - 报告为 dataclass：setting（kind/name/version）+ impacts + total；
  - 检索失败（单层查询异常）只 stderr 告警并跳过该层，不整体失败。
- tests：关键词提取（名称命中、内容片段命中、短词过滤、去重）、跨层命中与来源、排除自身与自身版本、归档笔记不命中、排序与 limit、无影响空报告、未知设定 NOT_FOUND、单层失败降级。

### 做到什么程度

- 核心服务落地且有单测；既有 779 测试全绿（不接 CLI、不改既有命令输出）。

### 验收标准

- 单测覆盖上述全部路径；零影响报告与未知设定错误路径正确。

### 验证方式

pytest + ruff + pyright + 宪法校验。

### 暂不做

- CLI（L2）、语义相似命中（N7 已可扩展但本阶段不用）、自动修订提示、跨作品影响。

## 子阶段 L2：CLI 与端到端

### 做什么

- `cli/setting.py`：新增 `setting impact <作品ID> <设定ID> [--limit N]`：
  - 无影响输出 `no impact found for <设定名> v<N>`；
  - 有影响输出标题行 `impact for <设定名> v<N>（共 M 条）：` + 每条一行 `[层标签] <来源>：<片段>`；
  - 未知设定/作品按全局退出码语义（业务错误 1）。
- `cli/setting.py` 或独立：`setting impact --verbose` 输出关键词集（可选，便于排查，默认不输出）。
- tests：端到端「建设定 → 写入含设定名的草稿正文、对话、伏笔、笔记 → setting impact 全部命中且顺序/来源正确 → 修订设定后 impact 仍可跑 → 无引用时 no impact」；未知设定/作品、limit 截断、退出码。

### 做到什么程度

- 端到端可断言：改动设定前跑一次 impact 即知波及面；只读不阻塞。

### 验收标准

- 端到端用例 + 失败路径；smoke_m3 仍 SMOKE OK；stress_m3 无回归。

### 验证方式

pytest（新增用例）+ smoke_m3 + stress_m3。

### 暂不做

- 自动在 setting revise 后提示影响（可后置为自然行为）、语义相似影响（N7 扩展）、影响报告导出。

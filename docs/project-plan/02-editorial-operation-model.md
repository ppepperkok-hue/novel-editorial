# 03a 编辑部运作模型（Operating Model）

## 一句话

编辑部不是流程流水线，而是一个分层协作的有机体：组织分层、判断分层、信息分层三者叠加，老板（作者）在关键处拍板，各层各司其职，协作自然发生。

## 三种分层

### 1. 组织分层

老板（作者）→ 主编 → 责编 → 写手 / 审稿

- 老板：作者本人，拥有最终决定权，可随时介入任意层。
- 主编：把控整体方向与关键决策，主持讨论，常规决策拍板。
- 责编：跟稿、提日常意见、把关章节质量。
- 写手：执行创作，对自己笔下的内容负责。
- 审稿：连贯性、逻辑、风格一致性的检查者。

角色可按作品配置，默认提供一套编辑部班子。

### 2. 判断分层

每一层都有属于自己的判断权：

- 老板拍大方向与关键决策。
- 主编拍常规决策。
- 责编提跟稿意见，可要求返工。
- 写手对自己的句子负责，可以反驳意见。
- 审稿对连贯性负责，可以退稿。

判断有归属、有立场、可被记录和追溯。层级之间是协作关系，不是审批关卡：不是每件事都要层层盖章，写手写一句不需要请示，责编意见也不必次次等主编过目。

### 3. 信息分层

- **按职责裁剪**：每层默认只看到完成自己判断所需的最小充分信息。写手拿写作记忆包（章纲、相关设定、角色状态、风格要求）；责编拿正文与跟稿依据；主编拿全局状态；老板拿方向与关键节点。
- **向上沉淀**：创作事实、决策、成果自动沉淀到对应层级（作品档案、创作日志、伙伴记忆、叙事追踪）。
- **向下分发**：上层的方向、约束、决策在下一轮创作中自然生效。
- **按需检索**：需要时检索相关记忆片段带入上下文，每条带来源引用。
- **可穿透、可追溯**：层级之间不是墙；老板能随时下探任意层，伙伴有需要也能查更深的信息，只是默认不看。

## 为什么这是地基

- 保证伙伴完整度：各有视角、各有记忆，不是共享一个真相的工具。
- 控制上下文成本：不全量灌入，按需取用。
- 保证判断质量：信息不淹没关键点。
- 保证过程可见、可介入：老板穿透，来源可溯。

## 从运作模型看“知识库”

知识库不是一份全量共享文件，而是随分层流动的信息体系：

- **作品档案**：客观事实（设定、角色、关系、时间线），由确认与创作沉淀。
- **创作日志**：过程事实（讨论、决策、版本、返工原因），自动记录。
- **伙伴记忆**：每个伙伴的私有笔记、印象、情绪，允许主观与分歧。
- **叙事追踪**：工程线索（伏笔埋设与回收、角色目标状态、悬置钩子）。

四类信息各有归属层、默认视图与检索路径；向上沉淀、向下分发、按需取用、来源可溯。

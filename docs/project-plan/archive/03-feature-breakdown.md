# 03 功能拆解（Feature Breakdown）

## 功能清单

优先级：P0 必须 / P1 应该 / P2 可以。每个功能标注所属目标。

### F1【P0 / G1】作品工作区

作为作者，我想要为一部作品建立独立的工作区（标题、体裁、简介），以便围绕它开展所有协作。

前置：无。

### F2【P0 / G1】自然对话协作

作为作者，我想要在作品里与伙伴们自由对话、@指定伙伴或全员参与，以便用最自然的方式讨论和共创。

前置：F1。

### F3【P0 / G1】伙伴班子配置

作为作者，我想为作品配置参与协作的伙伴（默认有主编 / 责编 / 写手 / 审稿），以便按作品需要组建班子。

前置：F1。

### F4【P0 / G1】草稿与版本

作为作者，我想看到伙伴产出的草稿及其版本历史，以便随时对比和回退。

前置：F2。

### F5【P0 / G1】反馈与返工

作为作者，我想对草稿提意见、指定伙伴修改、保留修改原因，以便作品被真正磨过而不是一次成型。

前置：F2、F4。

### F6【P0 / G1】作者介入

作为作者，我想随时接受、拒绝、给指示，以便任何决策都由我拍板。

前置：F2。

### F7【P0 / G2】AI 味质量门

作为作者，我想在产出通过前看到可量化的 AI 味检测报告（词表命中 / 密度 / 句式重复 / 风格一致性），以便守住无 AI 味这条线。

前置：F8。

### F8【P0 / G2】风格锚点

作为作者，我想为作品定义风格基准（风格样例、禁忌词、偏好），以便写作与检测都对照同一个标准。

前置：F1。

### F9【P1 / G2】AI 味定位与改写建议

作为作者，我想知道 AI 味具体在哪些位置、怎么改，以便快速返工。

前置：F7。

### F10【P0 / G3】伙伴档案

作为作者，我想为每个伙伴建立和编辑完整档案（身份 / 性格 / 价值观 / 审美 / 情绪基线 / 工作习惯 / 弱点 / 人际预设 / 私心），以便他们是有来历的人。

前置：F1。

### F11【P0 / G3】立场与记忆引用

作为作者，我想看到伙伴依据自己的档案与记忆说话、坚持立场、拒绝违背自己判断的任务，以便他们是伙伴而不是工具。

前置：F10、F14。

### F12【P1 / G3】伙伴状态沉淀

作为作者，我想看到伙伴的情绪与状态随互动变化并被记录，以便他们是有温度的。

前置：F10、F14。

### F13【P0 / G4】设定库

作为作者，我想把设定、角色、关系、伏笔、时间线结构化沉淀，以便它们成为作品的共同记忆。

前置：F1。

### F14【P0 / G4】记忆检索

作为作者，我想让伙伴在创作时自动引用相关旧设定且引用可追溯，以便跨章节不丢。

前置：F13。

### F15【P0 / G4】作品隔离

作为作者，我想让多部作品的数据互不串扰，以便同时管理多个项目。

前置：F1。

### F16【P1 / G4】伏笔追踪

作为作者，我想记录伏笔的埋设与回收，以便长线叙事有据可查。

前置：F13。

### F17【P2 / G5】快速开始与示例

作为新作者，我想按 README 在干净环境 30 分钟内跑起示例编辑部并产出第一段内容，以便开箱即用。

前置：核心功能可用。

### F18【P2 / G5】配置与常见问题文档

作为新作者，我想看到配置说明和常见问题，以便不依赖作者本人解释。

前置：F17。

## 做 / 不做清单

**做**：上表 F1–F18。

**不做**：

- 自动发布到外部平台（番茄、起点等）。
- 图形前端面板与桌面应用（后置；先行 CLI / API 交互）。
- 多作者实时共编。
- 一键从想法到完结的全自动流水线。
- 成本核算中心 / 预算仪表盘。
- 外部知识库自动导入（后置）。

## 依赖关系

- 基础层：F1 → F2 / F3 / F8 / F10 / F13 / F15
- 协作层：F2 → F4 → F5；F2 → F6
- 质量层：F8 → F7 → F9；F7 为 F5 提供依据
- 记忆层：F13 → F14 → F11 / F12；F13 → F16
- 开源层：核心功能可用 → F17 → F18

无循环依赖。

## 反盲从三问

1. 这是需求还是方案？“自然对话、草稿版本、质量门、伙伴档案”是功能需求；“用 LLM 工具调用实现”“对话协议”是方案。
2. 依据是什么？每个功能都能回溯到 G1–G5 目标；砍掉的功能都无法回溯源目标。
3. 不做会怎样？砍掉的都是非核心（发布 / 面板 / 共编 / 一键完结 / 成本中心），不影响“一起创作”主线。

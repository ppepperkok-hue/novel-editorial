# 01 核心价值（Core Value）

## 一句话价值主张

让一个人也能拥有一间真正分层运作的文学编辑部：作者是老板，一群有完整人格、有判断、有记忆的 AI 伙伴各司其职，通过自然协作，把网文、同人、短篇、长篇等各类文学创作，一步步磨成真正想写的样子。

## 核心用户

- 主要用户：个人创作者。一人操盘一部或多部作品，AI 伙伴作为分层运作的编辑部协作。
- 次要用户：开源使用者。外部作者拿来即用，需要配置友好、文档清晰、不依赖作者本人解释。

## 核心场景（从真实编辑部运作出发，不绑定体裁）

1. **老板下令产出一部作品**：从一句指令开始，编辑部经过选题、方向、大纲、样章、创作、审稿、交付，分层协作走完全程；老板只在关键处拍板，可随时下探任意一层。
2. **日常创作协作**：写手写、责编跟、审稿查、主编把控，讨论与返工自然发生；作者随时介入，接受、拒绝、给指示。
3. **多部作品并行**：老板同时管理多个编辑部，各部作品的记忆与数据互不串扰。

## 核心价值构成

- **分层运作是骨架**：组织分层（老板→主编→责编→写手/审稿）、判断分层（各层各有判断权）、信息分层（按职责取用、向上沉淀、向下分发、可穿透可追溯）。详见 [02-editorial-operation-model.md](02-editorial-operation-model.md)。
- **创作与协作本身是核心**：开会、讨论、批注都只是方式，不是目的；协作要自然，不强制流程关卡。
- **作品不能有 AI 味**：质量门可量化，且作者始终可以介入。
- **AI 伙伴是完整的人**：有档案、有立场、有审美、有记忆，会坚持判断，而不是工具人。
- **作者是老板，能穿透一切**：关键决策由作者拍板，任何一层都向老板敞开。

## 价值边界（明确不做）

- 不自动发布到外部平台（番茄、起点等）。
- 前端面板 / 桌面应用后置，先把创作与协作核心做扎实（先行 CLI / API 交互）。
- 不做多作者实时共编（首个版本面向单作者 + AI 编辑部）。
- 不做“一键从想法跑到完结”的全自动流水线——创作是逐步的、可介入的。
- 不做成本核算中心 / 预算仪表盘。
- 不自动导入外部知识库（后置）。

## 为什么现在做 / 为什么重写

前身以 n8n 编排固定日更流水线：过程不可见、角色是表演、产出 AI 味重、各环节耦合过紧。用户实际试用后判定整体逻辑与真正想要的不符，决定推倒重来。重新推导后确认：编辑部本质是一个分层协作的有机体，而不是流程机器。新版本以分层运作为骨架重建，旧版仅作参考。

## 反盲从三问

1. 这是需求还是方案？“分层运作、自然协作、无 AI 味、伙伴完整”是需求；“对话协议”“检索算法”“质量门公式”是方案。
2. 依据是什么？用户对前身实际试用的直接反馈，加上从真实编辑部运作出发的逐层推导，并经用户逐项确认。
3. 不做会怎样？没有分层，系统会退回全量信息灌入和审批式流程，重蹈前身“流水线 + 表演角色”的覆辙。

## 约束与风险（随时更新）

- 信息分层是控制上下文成本的关键，但分层不当会造成信息缺失：需要“按需取用 + 来源可溯 + 老板可穿透”三件套兜底。
- 去 AI 味没有绝对标准：需要可量化质量门 + 作者可介入的兜底。
- AI 伙伴完整度与上下文成本冲突：需要记忆分层与上下文预算。
- 开源可用性：默认配置要开箱即用，文档与示例要完整。
- 时间：用户明确可以慢慢来，按阶段迭代，不做大爆炸式交付。

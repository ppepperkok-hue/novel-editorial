承接 `agent自由度评估.md` 第七节的名实差距清单：已修复拒绝权默认开、关系排序、会议 agency/outbox 通道（提交 a76bc3d）。本文评估剩余两条：**rework 即时重写**与**记忆可控性**。

## 一、R5-1 · rework 即时重写（消息驱动管线内重写）

### 现状

- 留言携带 `decision=rework` 时，`_handle_outbox` 只创建高优行动项（`按留言重做`），由后续触发点兑现；
- 管线内已有 `_review_retry`：质量门失败 → 发打回消息 → 写手回复修改意图 → 重写 → 回审（`REVIEW_RETRY_MAX=1` 上限）。

### 技术可行性

| 项目 | 评估 |
| --- | --- |
| 复用点 | `_review_retry` 的完整重写回环可直接泛化；消息已有 `reply_to` / `ref_chapter_id` 字段 |
| 主要难点 | 重做请求要绑定具体章节/轨道；跨轨、跨日、无章可重的请求必须安全回落行动项 |
| 防循环 | 同一章每次运行重写上限 1 次（`REWORK_MAX` 可配）；超限落行动项 + audit；预算熔断不变 |
| 风险 | 中：只在「当前轨道内、写手自审时带 rework 且消息带 ref_chapter_id」触发即时重写，其余全部回落现状 |
| 工作量 | 中 |

### 工程表

| 步骤 | 内容 | 验收 |
| --- | --- | --- |
| R5-1-1 | `_handle_outbox` rework 分支改为：若 `reply_to` 消息带 `ref_chapter_id` 且等于当前轨道章节 → 返回即时重写请求（不建行动项）；否则维持现状（行动项） | 两分支断言 |
| R5-1-2 | `_run_track` 收集即时重写请求，质量门后若有请求则走泛化 `_review_retry`（写入重做理由 + 留言原文），成功后原消息 resolve('rework') | 即时重写全路径断言 |
| R5-1-3 | 防循环：同一章每次运行重写上限 `REWORK_MAX`（默认 1）；超限回落行动项 + audit 留痕 | 超限回落断言 |
| R5-1-4 | 测试：即时重写成功、超限回落、无 ref_chapter 回落现状、resolve/audit 正确 | 单测全绿 |
| R5-1-5 | 全量回归（442 基线）+ 提交 | 全绿 |

### 成本

- 仅在有 rework 留言时多一轮重写（与现有打回成本同量级，低概率事件）；
- 月增量估算 <0.5 元；预算熔断不变。

## 二、R5-2 · 记忆可控性（让注入的记忆真的被使用）

### 现状

- `agent_context` 注入收件箱/待响应/心情/记忆/关系/承诺/行动项；
- 记忆按 importance + opinion 优先排序，但模型用不用不可控。

### 技术可行性

| 项目 | 评估 |
| --- | --- |
| 可做的 | ① 按 agent 角色过滤记忆类别（写手偏剧情/角色，审稿偏打回/质量，主编偏会议/决策），减少噪声提高聚焦；② JSON 输出型 agent（审稿/主编/会议/日记）增加可选 `memory_used` 字段并落库，形成「用了哪些记忆」的可观测痕迹；③ 写手正文场景用软要求（正文须体现记忆），不强制 JSON |
| 不可做的 | 无法保证模型 100% 使用记忆（模型行为层面），诚实声明 |
| 风险 | 低：过滤与可选字段均向后兼容，缺失默认空 |
| 工作量 | 小-中 |

### 工程表

| 步骤 | 内容 | 验收 |
| --- | --- | --- |
| R5-2-1 | `agent_context` 按 agent 角色过滤记忆 category（config 映射表可配）；无映射时维持现状 | 过滤断言；无映射不回归 |
| R5-2-2 | 审稿/读者审/主编终审/会议发言的 JSON 提示增加可选 `memory_used`（数组，最多 3 条引用） | 提示词断言 |
| R5-2-3 | 解析 `memory_used` 落 `agent_activity`（类型 `memory_used`），前端 Agent 管理显示记忆使用记录 | 落库/前端渲染断言 |
| R5-2-4 | 写手任务 prompt 增加「正文须体现最近记忆」软要求（不破坏纯正文输出） | 提示词断言 |
| R5-2-5 | 测试 + 全量回归（442 基线）+ 提交 | 全绿 |

### 成本

- 零新增 LLM 调用；prompt 略增（几十 token/调用）；
- 可观测性提升：面板能看到每章/每次发言实际引用了哪些记忆。

## 四、诚实边界

- rework 即时重写只覆盖「当前运行内、留言绑定当前轨道章节」的场景；跨轨、跨日、历史章节的重做仍走行动项回路；
- 记忆可控性提升的是使用率与可观测性，不是 100% 保证；验证靠 `memory_used` 痕迹而非断言模型行为。

## 五、执行顺序

R5-1（即时重写）→ R5-2（记忆可控）→ 每步全量回归 + 审查报告更新 + 提交推送。R5-1 高风险步骤先 dry-run 全链再灰度。

# 编辑部人格化 · 升级报告与工程表（2026-08-11）

本文是后继严谨开发的基准：升级性能评估、11 位 agent 细化准备、前端完全重构
准备、以及整合后的工程表。所有数字以当前代码为准（279 后端 + 8 前端测试）。

## A. 升级性能评估

### A1. 架构扩展点

| 层 | 扩展点 | 现状 | 后继扩展成本 |
| --- | --- | --- | --- |
| 数据层 | `db._migrate` 幂等 | 26 张表，迁移机制现成 | 新增表/列低成本；四张新表已规划 |
| 注入层 | `agent_tool_loop.build_system` | 唯一 system 组装点 | 快照可插拔；新快照（读者反馈/平台数据/同事动态）按同一模式加 |
| 调度器 | `editorial_daily._Ctx` + `_agent` | 单入口、状态贯穿 | 动态分派/打回走开关灰度；完结/留痕/人物卡为增量 |
| 接口层 | web_api 路由注册表 | GET/POST_ROUTES 已建立 | 新端点登记即可，不再进巨型 handler |
| 会议 | `meeting_session` 状态机 | 轮次制 + 取消/超时自愈 | 插话→自由对话是最大改造，分两期 |
| 前端 | 页面注册表 NAV/PAGE_META | hash 路由 + 手写 if 链 | 新增页面低成本；巨型组件重构见 C |

### A2. 容量与成本

- 数据容量：消息/记忆/关系/承诺为行级 SQLite，日更 15 次调用 × 每次数条，
  年量级百万行内，索引后查询无压力；日记保留 8 周自动清理，消息/记忆按
  novel_id 隔离 + 可清理。
- 注入成本：每次调用 ~1.6K token，月增量 ~3.5–4.5 元（预算 4%）；按 agent
  过滤后更低。消息/承诺/关系零额外 LLM 调用（合并进周记一次调用）。
- 延迟：prompt +1.6K token 增加数秒，对 20–60 分钟日更无感。
- 熔断：预算熔断 + 重试上限 + 打回轮次上限；S10/S13 有 fixed 模式开关。

## B. Agent 细化准备（11 位）

现状：全部 agent 已有人物档案 7 字段（姓名/身份/性格/说话风格/价值观/核心关注点/
情绪基线）+ 日常/日记/周记/会议四模式（knowledge_keeper 无日常任务，只有维护模式）。

细化方向：档案增加「工作习惯 / 弱点与盲区 / 人际预设（对谁信任、与谁常有摩擦）/
激励源（什么驱动他）/ 私下想法（与公开发言的差异）」；新增「消息模式（收到同事
留言如何回应）」「认领模式（看到任务板空活如何表态）」两段提示词（随 S3/S6/S8 加入）。

| Agent | 身份 | 细化要点（记忆/关系/消息/驱动） | 归属步骤 |
| --- | --- | --- | --- |
| planner 策划官 | 出大纲/圣经 | 记忆：蓝图演化与题材兴趣；驱动：被采纳的大纲 → 信任↑ | S3/S7 |
| guard 世界观守护 | 设定一致性 | 关系：对吃书零容忍，是摩擦主要来源；消息：拦截时留言说明依据 | S4/S7 |
| writer 墨白 | 叙事写手 | 记忆：记得被打回的原因；承诺：交稿承诺；消息：回复审稿理由 | S3/S4/S6 |
| editor 润色 | 去 AI 味 | 关系：与 writer 磨合；消息：返稿意见 | S4/S7 |
| reviewer 守正 | 逻辑审稿 | 消息：打回时说明六类理由；关系：打回多 → 与写手 friction↑ | S4/S7/S11 |
| reader 读者审稿 | 读者视角 | 驱动：读者数据反馈；记忆：低完读率章节 | S3 |
| eic 主编 | 终审/主席 | 驱动：分派权与信任权重；关系：信任高的成员提案优先 | S7/S10 |
| memory 记忆官 | 提炼/归档 | 记忆：记忆系统的管理员，负责压缩与时间线 | S3/S6 |
| work_meta 作品资料 | 书名/简介 | 驱动：作品资料被采纳；低协作需求（可不注入快照） | S3（过滤） |
| ending_judge 完结评估 | 完结时机 | 驱动：周会启动；记忆：剧情进度/伏笔回收率 | S13+ |
| knowledge_keeper 博闻 | 知识维护 | 驱动：定时+手动；低协作需求（可不注入快照） | S3（过滤） |

## C. 前端面板完全重构准备

### C1. 现状问题

| 问题 | 证据 | 影响 |

## E. 开发纪律（后继每步强制执行）

- 每步跑 `python run_tests.py`（279+）、`cd webapp && npm test && npm run build`、
  `node tools/validate_workflow_deep.mjs`。
- 修 bug 先写失败测试；新表/列走 `_migrate` 幂等；大 payload 走文件；中文 UTF-8。
- S10/S13 高风险步：先灰度（fixed 默认），验证稳定后再切换默认。
- 前端重构不改变后端契约；后端接口变更先改前端调用再删旧端点。
- 每阶段结束更新本工程表与 README，数字与代码一致；审查报告落 `docs/reviews/`。

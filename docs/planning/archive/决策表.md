# 开工前决策表（三项拍板 + 两个运营选择）

> 决策后即可进入 Phase 1 真实运行。每项都给了推荐默认值，先按推荐走，
> 跑出数据再调整也不迟。

**目标定位**：副业、持续盈利、不以此谋生。据此建议月度成本上限 ¥100-200，
先用小号跑通全链路并积累数据，再决定是否扩大书量。

## 决策一：目标平台

| 选项 | 适合 | 代价 / 风险 |
|---|---|---|
| **番茄小说（推荐）** | 全自动生成正文并发布；工具链成熟，有非官方接口与定时发布 | 必须如实声明 AI 内容；平台严打批量低质 AI 文，质量门要过硬 |
| 起点 / 阅文 | 想走官方渠道稳一点 | 官方口径「严禁非真人自动化批量生成核心内容」，只能半自动，人工过目后官方客户端定时发布 |
| 晋江 | 女性向题材 | 只允许 AI 辅助到粗纲，全自动不可行 |
| 海外平台 | 中文之外的尝试 | 政策相对宽松，但流量逻辑不同，需另做调研 |

## 决策二：每月 API 预算

| 档位 | 示例 | 单章成本 | 月成本（日更 2 章） |
|---|---|---|---|
| **入门（推荐起步）** | DeepSeek | ¥0.1-0.5 | ¥6-30 |
| 中档 | Claude Sonnet 级 | ¥1-4 | ¥60-240 |
| 旗舰 | Claude Opus 级 | ¥10-30 | ¥600-1800 |

建议：先用入门档把「质量门 + 审稿循环」跑熟，确定能稳定过审后再升档。
测算参考：`python -m novel_editorial.economics --cost-per-chapter 0.3 --listening-share 600`
可看成本、全勤、分成与盈亏平衡的联动结果。

## 决策三：技术路线

| 选项 | 适合 | 说明 |
|---|---|---|
| **直接用 novel-editorial 脚手架（推荐）** | 想最快跑起来 | 零依赖、29+ 测试全绿，OpenAI 兼容模型即插即用，发布适配器已留好 |
| n8n 可视化编排 | 想看得见流程、不会改代码 | 需要把现有模块翻译成 n8n 节点，多一步迁移 |
| fork OpenNovel（LangGraph） | 想深度自研、扩平台 | 结构完整，但依赖 Claude Code 与更多组件 |

## 运营选择一：账号策略

- **小号试错（推荐）**：先用小号跑通全链路，确认过审率和流量表现，再决定是否上主号。
- 直接主号：省事，但封号 / 限流风险直接落在主账号上。

## 运营选择二：更新频率

- 默认日更 2 章（约 4000-6000 字/日，符合番茄全勤档位）。
- 存稿池安全线 3 章：每日新增存稿必须 ≥ 每日发布数，否则自动断更预警。

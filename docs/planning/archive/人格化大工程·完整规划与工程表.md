# 人格化大工程 · 完整规划与工程表（2026-08-11）

定位：人格化的**骨架已全部完成**（S1–S15 数据层/注入/消息/关系/任务板/会议、P 系列 11 份人格档案、F 系列前端）。本规划是「血肉」阶段：让 agent 的话真正改变自己与系统接下来做的事。本文是后继严谨开发的基准，所有数字以当前代码为准（371 后端 + 15 前端测试）。

## 一、骨架已完成，血肉缺什么

| 层 | 骨架现状 | 血肉差距 |
| --- | --- | --- |
| 身份 | 11 份人格档案（性格/价值观/私心/激励源） | 人格只影响措辞，不影响决策与分派偏好 |
| 记忆 | 日记/周记/事件记忆全量注入 | 注入与否、用不用全看模型，无强制引用 |
| 关系 | trust/friction/familiarity 有事件钩子 | 只是提示词文本，不改任何行为 |
| 消息 | 收件箱/outbox/审稿打回 | 除审稿打回外，留言不触发「响应→重做」回路 |
| 驱动 | 任务板认领/承诺/行动项/主编分派灰度 | 认领不改流程；分派默认 fixed；议题只进议程 |
| 表达 | 会议自然发言 + JSON 结构化输出 | 日常输出无 notes 出口；说话不改行为 |

一句话：**骨架让 agent 像「有名字的演员」，血肉要让他们变成「有决定权的编辑」。**

## 一·五、架构原则：开工即主驱动（已确认 2026-08-11）

整个编辑部收进一个生命周期：**开工是主驱动（门），内部驱动决定这一天怎么过（生活）**。

- 不开工 = 编辑部待命：agent 不主动工作、零 LLM 成本；消息与议题可以积累（「下班后的念头」），面板可见。
- 开工 = 打开一天：晨会分派、任务板、承诺兑现、消息处理、关系反馈、自主行动、会议全部在这一天内被激活。
- 收工 = 关上门：两级完工，今日事项落库，遗留明日带出。
- 内部驱动不是独立常驻进程，而是「工作日内的活动类型」；它们决定开门后这一天怎么过，不替代开工。
- 两个边界：维护任务（知识管家/热点采集）收进工作日作为「顺带事务」，同时保留受控独立触发入口；agent 的自主行动只在开工后发生，外部副作用（发布/建书/删书/完结/采纳知识）永远锁在开工闸门之后。
- R0–R4 全部挂在这个主驱动之下；R4 的编辑部工作日设计已按此形状搭建。

## 二、总体蓝图：五阶段自由度阶梯

| 阶段 | 名称 | 核心能力 | 像人程度（诚实估算） |
| --- | --- | --- | --- |
| R0 | 打通说话→行为通道 | 分派生效、认领兑现、表达出口、议题闭环 | 20% → 35% |
| R1 | 行为选择权 | 接受/拒绝/替代方案、消息驱动回路、认领自主执行 | 35% → 55% |
| R2 | 社会性 | 关系影响分派/措辞/协作，情绪影响表达与主动性 | 55% → 70% |
| R3 | 自主与成长 | 受控主动行动、观点演化、反思与技能成长 | 70% → 85% |
| R4 | 编辑部生活 | 工作日节律、会议泛化、仪式感 | 85% → 90%+ |

剩余 ~10% 是 LLM 本身的局限（真实动机、持续意志、非语言感知），诚实说明，不宣称能达到。

### 改造后自由度九维展望（R0–R4 全部完成后）

| 维度 | 当前 | 改造后 | 说明 |
| --- | --- | --- | --- |
| 触发 | ★ | ★★ | 仍由老板开工/受控触发主导；agent 可在工作日内自主执行安全动作，但不能自行开门 |
| 任务 | ★★ | ★★★★ | 分派生效、可拒绝/提替代方案、认领优先执行、议题变行动项 |
| 流程 | ★★ | ★★★★ | 主编分派、消息驱动重做、打回协商；质量门/预算仍不可绕过 |
| 表达 | ★★★ | ★★★★ | notes 出口、接受/拒绝/替代方案、情绪语气注入 |
| 工具 | ★★★★ | ★★★★ | function calling 保持，接入更多知识源 |
| 记忆 | ★★★ | ★★★★ | 观点演化时间线、反思成长注入决策 |
| 关系 | ★★ | ★★★★ | 关系影响分派排序与措辞（软影响，非硬权重） |
| 主动性 | ★★ | ★★★★ | 安全动作白名单内自主执行，全部留痕 |
| 硬约束 | 护栏 | 护栏 | 外部副作用永不自主，授权分层不变 |

诚实边界：即使全部完成，agent 依然不能「当家做主」——开门权、外部副作用、预算上限永远在老板与系统手里；记忆的「用不用」仍取决于模型。自由度从「能说话」升到「能选择 + 能办安全事」，但不是「能自主决策一切」。

## 三、授权分层（红线，不可放开）

| 层级 | 动作 | 说明 |
| --- | --- | --- |
| 永不自主 | 外部发布、建书、删书、完结停更、采纳知识、超预算调用 | 永远由老板或受控调度器执行 |
| 可自主（安全动作） | 写检查报告、更新知识草稿、发消息、投议题、认领任务、提方案 | 落库留痕，不触外部副作用 |
| 可灰度 | 分派响应（接受/拒绝/替代方案）、行动项自行回填、关系软权重 | 开关控制，失败降级 |

## 四、技术可行性评估

| 阶段 | 技术可行性 | 与现有架构兼容 | 主要风险 | 工作量 |
| --- | --- | --- | --- | --- |
| R0 四刀 | 高（全是数据层/提示词层机械扩展，`_dispatch`/`_writer_task`/mailroom/activity 现成） | 高 | F1 分派输出不稳定 → 降级 fixed 已有 | 小×4 |
| R1 行为选择权 | 中高（任务响应需新增调用与裁决逻辑；消息回路泛化审稿打回模式） | 中（动 `editorial_daily` 主序列，需灰度） | **最高**：agent 乱拒绝/死循环 → 拒绝上限+主编兜底+开关 | 大 |
| R2 社会性 | 高（关系/情绪数据已有，只接行为） | 高 | 关系权重放大不稳定 → 软文本引导+排序函数可回退 | 中 |
| R3 自主与成长 | 中高（安全动作白名单+控制台，观点时间线已有雏形） | 中（主动性需新执行通道） | 自主动作失控 → 白名单+audit 全留痕 | 中-大 |
| R4 编辑部生活 | 高（工作日/会议泛化规划已完成） | 高 | 节奏拖长日更 → 轻量调用+开关 | 中×2 |

结论：**无技术死路**。R1 是最大风险点，走「固定模式 + 灰度开关 + 降级兜底」安全路径。

## 八、需要老板拍板的决策点

已确认：开工即主驱动（见第一章·五），R0–R4 全部挂在其下。

1. 阶段顺序是否认可：R0（四刀）→ R1（行为选择权）→ R2（社会性）→ R3（自主成长）→ R4（编辑部生活）？还是调整优先级（例如先做 R1 的消息回路）？
2. 授权分层是否认可：安全动作（写报告/发消息/投议题/认领/提方案）可自主，外部副作用永不自主？
3. 每个阶段完成即汇报再进入下一阶段，还是您希望按 R0→R4 一口气规划完再统一执行？
4. R1 的「拒绝权」是本次大工程里最有争议的一刀：写手可以拒绝分派并给替代方案，但每轨最多 1 次、超限主编兜底。是否按此设计？

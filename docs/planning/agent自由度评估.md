# Agent 自由度评估报告（2026-08-11）

## 一、评估方法

按 9 个维度逐一核对代码现状，每个维度给出「自由度等级」（1~5 星）与代码证据。评估基于：调度器 `editorial_daily.py`、工具循环 `agent_tool_loop.py`、协作上下文 `agent_context.py`、任务板 `services/activity.py`、关系 `tools/relations.py`、11 份人格档案 `prompts/agents/*.md`、会议引擎 `agent_meeting.py`、配置开关 `config.py`。

## 二、自由度矩阵

| 维度 | 自由度 | 现状 | 关键证据 |
| --- | --- | --- | --- |
| 触发 | ★ | agent 完全由调度器/会议/手动接口驱动，没有任何自主启动机制 | `editorial_daily.daily()` 固定管线；`/api/agent/run` 手动单跑；议题池只提示用户，不自动开会 |
| 任务 | ★★ | 任务板有认领/指派/优先级，但日更主管线固定分派，认领不改变主流程 | `activity.claim_action` 存在；`DISPATCH_MODE=fixed` 默认，editorial 模式灰度关闭 |
| 流程 | ★★ | 有审稿打回协商、灰度开关，但默认固定双轨 | `_review_retry`（`REVIEW_RETRY_MAX=1`）；A/B 双轨硬编码；`MEETING_MODE=rounds` 默认 |
| 表达 | ★★★ | 人格档案丰富（11 份，含性格/价值观/情绪/私心），会议有自然发言，但日常输出被 JSON 模板强约束 | 写手直接输出正文；审稿强制 `{verdict,score,must_fix}`；会议强制六段 JSON |
| 工具 | ★★★★ | function calling 自主调用知识库，无强制 tool_choice，可多次检索 | `get_knowledge` + `get_novel_knowledge`，本地检索 + 二次推理；outbox 发消息 |
| 记忆 | ★★★ | 多级记忆（日记/周记/会议/事件记忆）注入每次调用，但模型用不用不可控 | `agent_context.build_context_snapshot` 注入收件箱/记忆/关系/承诺/行动项 |
| 关系 | ★★ | trust/friction/familiarity 有事件驱动与注入，但只是提示词文本，不改变决策权重 | `relations.apply_event`；快照中「我与同事的关系」仅为文本 |
| 主动性 | ★★ | 能发消息（outbox）、投议题（topic_request）、认领任务，但不能自主执行任何行动 | outbox 落库；`_record_topic_requests`；claim 状态存在但主流程不用 |
| 硬约束 | 护栏 | 质量门/合规词/预算/字数不可绕过，属必要约束 | `quality_gate` 机械检查 + AI 味黑名单；preflight 预算/合规 |

## 三、名实差距：纸面自由 vs 实际自由

| 能力 | 纸面上有 | 实际上 | 差距原因 |
| --- | --- | --- | --- |
| 主编分派 | `DISPATCH_MODE=editorial` 灰度存在 | 默认 `fixed`，主编分派不生效 | 灰度未打开，缺少验证 |
| 任务认领 | 任务板可 claim | 日更管线固定指派写手 A/B，认领不影响管线 | 认领只改状态，未接入调度选择逻辑 |
| 关系影响 | 关系快照注入每次调用 | 只是文本，不改变任何决策 | 没有把 trust/friction 变成行为权重 |
| 消息协作 | outbox 可发消息、收件箱注入 | 对方收到后是否响应、是否改变行为不可控 | 无消息驱动的行为回路（除审稿打回） |
| 记忆连续性 | 记忆/日记/周记全量注入 | 注入与否、用不用全看模型 | 无强制检索/引用机制 |
| 议题提议 | 会中可投 topic_request | 只在下一次会议追加议题 | 没有「提议→行动项→兑现」闭环 |
| 主动行动 | — | 完全没有 | agent 无自启动机制（设计上保留给老板） |

## 四、结论

当前 agent 是「**有性格、有记忆、有工具、能说话的执行者**」：

- **自由度最高的是工具层**：function calling 自主检索知识库，这是最接近「人按需查资料」的部分；
- **表达自由居中**：人格档案给了真实质感，但日常输出被 JSON 模板限制，只有会议发言有自然语言空间；
- **自由度最低的是行为层**：何时工作、做什么、做几章全由调度器决定；认领、分派、关系、消息都只是「提示词装饰」，没有真正改变行为；
- **主动性停留在「说话」层面**：能发消息、投议题，但不能自主认领后执行、不能发起任务、不能改变流程。

一句话：**自由度是「被允许说什么」，还不是「被允许做什么」**。距离「真实文学编辑部」的差距，不在人格和记忆（已经很足），而在「行为选择权」——agent 说的话目前不能真正改变自己接下来做的事。

## 五、提升方向（供后续计划，非本期承诺）

1. **行为层自由**：打开 `DISPATCH_MODE=editorial` 并让主编分派真正决定写手选择；任务认领接入主流程（认领者优先执行对应任务）。
2. **决策点机制**：工作日「完成点决策制」（已规划）天然是自由度的提升——主产出完成后由老板/主编决定收工、开会还是继续，不再自动跑完。
3. **关系影响行为**：把 trust/friction 变成软权重（如 friction 高时主编更谨慎、写手重写时更自觉），以开关控制、可回退。
4. **消息驱动回路**：审稿打回已是唯一消息回路；扩展为「任何人可对任务留言 → 负责人响应后决定是否重做」，跑通后再谈自主行动。
5. **表达出口**：日常 JSON 输出增加 `notes`/`comments` 自然语言字段，让 agent 表达无法结构化的判断。
6. **议题闭环**：topic_request 消费后自动生成行动项（create_action），而非只进会议议程。

## 六、风险提示

- 自由度提升 = 不确定性提升：打回协商、认领、关系权重都可能让输出波动，必须保留质量门与熔断作为硬底线。
- 行为层自由需要「可解释」：agent 自主选择时必须在 audit/activity 留痕（选了谁、为什么），否则面板上会变成黑盒。
- 建议按「先决策点 → 再分派/认领 → 最后关系权重」的顺序小步开放，每步全量回归。

## 七、改造后复评（2026-08-11，R0–R4 全部完成后）

### 自由度矩阵（改造后）

| 维度 | 改造前 | 改造后 | 证据与说明 |
| --- | --- | --- | --- |
| 触发 | ★ | ★★ | 门内自主（agency 白名单真实执行）；开门权仍在老板，agent 不能自行开工 |
| 任务 | ★★ | ★★★★ | 主编分派默认 editorial 并注入写手任务；认领兑现（交稿标 done/未交稿涨摩擦）；会议议题转行动项；**但拒绝权开关默认 off** |
| 流程 | ★★ | ★★★ | 审稿打回协商 + 消息决策回路（rework/clarify/defer 落行动项）；决策点由老板控制；**写稿链本身固定，rework 不即时重写** |
| 表达 | ★★★ | ★★★★ | notes 出口落库并前端显示；会议自然发言；人物档案六套模式 |
| 工具 | ★★★★ | ★★★★ | function calling 自主检索保持；agency 白名单 5 类动作可执行 |
| 记忆 | ★★★ | ★★★★ | 观点演化时间线落 `agent_memories` 并优先注入；两级日记/周记 |
| 关系 | ★★ | ★★★ | 关系快照进分派输入；打回措辞随 friction 变化（`_review_tone`）；拒绝/采纳驱动事件；**无 trust 排序函数，影响仍是软性** |
| 主动性 | ★★ | ★★★★ | 白名单动作在日更链路真实执行；**但 agency/outbox 通道只挂在 editorial_daily._agent，会议/日记等通道不支持** |
| 硬约束 | 护栏 | 护栏 | 质量门/合规/预算/授权分层不变 |

### 名实差距（如实清单）

1. **拒绝权默认关闭**：`TASK_RESPONSE_MODE` 默认 `off`（代码能力已就绪，默认行为未启用）；
2. **关系排序未实现**：R2 工程表写了「信任高优先排序函数」，实施时因单写手轨跳过，目前只有关系快照注入（软影响）；
3. **rework 是行动项回路**：消息「重做」落为高优行动项由后续触发点兑现，不是管线内即时重写；
4. **agency 通道单点**：`_handle_agency` 仅在 `editorial_daily._agent` 调用；会议发言、日记、周记的输出不支持 agency/outbox 通用通道；
5. **记忆使用不可控**：记忆/观点注入 prompt，模型用不用无法保证；
6. **触发仍外部主导**：开门权、主产出触发永远在老板与调度器手里（设计如此，不算缺陷）。

### 结论

从「被允许说什么」走到了「能选择、能办安全事、说话算数」：任务与主动性是实质提升（分派、认领、议题、白名单都真实生效），表达与记忆也有可见进步。诚实估算是自由度从约 2 成走到约 6–7 成，处于上一轮预测的下沿。剩余 3–4 成缺口里，一部分是设计上不放开的（开门权、副作用、预算），另一部分是名实差距（拒绝权默认关、关系排序缺失、agency 通道单点、rework 不即时）——这些是下一步小步可补的。

### 下一步候选（按收益排序）

1. 灰度打开 `TASK_RESPONSE_MODE`（先 dry-run 全链，观察拒绝率与替代方案质量）；
2. 把 agency/outbox 通用通道扩展到会议与日记（复用 `_handle_agency` 模式，挂到 agent_meeting/write_diaries）；
3. 补关系排序函数（多写手/多候选场景下 trust 高者优先，确定性 + 开关）；
4. rework 即时重写（需防循环设计：上限 + 熔断 + 与行动项回路二选一）。

# 会议系统改造：工程表（自由会议 · 自主发言调度器）

承接《会议系统改造·最终评估报告》。本文件只含可执行步骤与验收/审查/回退；「为什么」见评估报告。

## 1. 审查机制（每步强制，不满足不进下一步）

### 步级审查
- 垂直切片 ≤100 行；写完 → 跑定向测试 → 主 agent 五轴自审（正确性/边界/错误处理/集成/安全）→ 本地提交。
- 自审对照：反模式族（裸 JSON 解析/吞错/假绿灯/硬编码/类型守卫/死代码）、四态（加载/空/错误/成功）、量化硬限制（文件 ≤500 行、函数 ≤120、嵌套 ≤3、单提交 ≤100 净增）。

### 阶段审查
- 每阶段完成跑 `powershell -ExecutionPolicy Bypass -File scripts/run_review.ps1 -Scope uncommitted`；P0/P1 清零、P2 登记临时报告。
- 全量回归：后端 `python run_tests.py`、前端 `cd webapp && npm test && npm run build`。
- 向老板汇报四要素：在干什么、影响什么、验证了什么、下一步。

### 收尾分片审查（阶段 7 后）
- `scripts/run_review.ps1 -Scope slices` 六片并行；汇总 → 核实层（confirmed/false_positive）→ 修复（先写失败测试）→ 回归检查层 → 归档 `docs/reviews/rounds/`。

### 测试纪律
- 临时库 + mock LLM + 不触真实番茄/webhook；SSE 用 MockEventSource；@路由纯函数单测（中文边界）；修 bug 先写失败测试。

## 2. 分阶段步骤

### 阶段 0 · 数据层

**步骤 0.1 表结构与迁移**
- 内容：db.py 幂等新增 `meeting_messages`（id/session_id/seq/from_agent/role/kind/body/mentions JSON/status/created_at）、`pending_interactions`（id/session_id/agent/kind(approval|clarify)/payload JSON/status/created_at/expires_at/resolved_at/resolution）；`meeting_sessions` 加 `mode`（默认 rounds）。
- 验收：重复迁移不报错；PRAGMA 断言通过；旧 transcript 回退读取可用。
- 测试：迁移幂等；511 后端测试全绿。
- 审查：步级自审；阶段审查（SQL 全部参数化）。
- 回退：删表回滚（数据可重建）。

### 阶段 1 · @提及路由与执行器桥

**步骤 1.1 @提及解析器 `meeting_mentions.py`**
- 内容：参考 hermes mention-routing 移植：`find_mentions(content, names)`、`strip_mention_tokens`、结构化 mentions JSON；中文标点边界、@all、防误判（邮箱/URL）。
- 验收：单测覆盖 `@守正`、`@all`、`@守正，回应墨白`、邮箱不误判。
- 审查：纯函数单测即验收。

**步骤 1.2 执行器桥 `meeting_executor.py`**
- 内容：`reply_to_mention(conn, session_id, agent, event)`：上下文 = 材料 + 历史尾截断（阶段 2 前先 N=20 条） + 该编辑周记/心情 + 事件消息 → `agent_tool_loop.run`（人格/记忆/知识工具）→ 输出解析（六段或 `{speak:false}`）→ 落 `meeting_messages` → 广播；失败重试一次，再失败留痕 `no_speech`+audit。
- 验收：dry-run @单人/@多人/@all 正确；输出六段；LLM 异常不中断会话且显式留痕。
- 审查：F1/F3/F4/F7 族扫描；阶段审查。
- 回退：mode=rounds 即全回旧路径。

### 阶段 2 · free 事件循环与自主发言（核心）

**步骤 2.1 事件循环线程 `meeting_free_loop.py`**
- 内容：`start_free_session`（起 daemon 线程）：事件队列（用户消息/@/审批结果/冷场计时）→ 逐事件调度；`advance_session` 在 free 下仅投递事件并返回（不阻塞）；心跳更新 `current_agent`/`heartbeat_at`；启动时扫描 running free 会话标记 `interrupted`（评估报告 A2）。
- 验收：事件按序处理；advance 不阻塞；重启后 running→interrupted 且消息不丢。
- 测试：事件队列/顺序；恢复扫描；并发投递幂等。

**步骤 2.2 接话决策器 `meeting_speaker.py`**
- 内容：候选 = 被 @ 必答 + 关注点关键词预筛 top K（K 默认 2）；排除 busy/冷却 agent；每事件候选上限 K+@数；输出候选名单 + 依据（供审查）。
- 验收：@守正 必答；未 @ 仅相关 agent 进候选；上限生效。
- 测试：预筛单测；上限断言。

**步骤 2.3 并行发言池与保险丝**
- 内容：`ThreadPoolExecutor(max_workers=3)` 并行调 `meeting_executor`；同 agent 最小间隔 60s；全局速率上限；冷场计时 30s（无人发言→触发候选编辑自主抛话题或主席推进）；成本/调用熔断（settings：单会议上限，默认 300 次调用或 ¥20）。
- 验收：dry-run 无人 @ 也自然接龙；允许全部沉默（落 no_speech）；冷却/熔断生效；50 条事件模拟消息量有界。
- 测试：并行/间隔/沉默/熔断；冷场计时（mock 时钟）。
- 审查：锁与并发专项（F7/F9）；阶段审查。

**步骤 2.4 基础上下文管理（压缩前置）**
- 内容：每事件注入历史 = 摘要锚点 + 最近 N 条（N 默认 20，字符上限 30k）；超限触发摘要（复用 compress_history 逻辑）并写 `compressed_at`；断线重连拉取含锚点。
- 验收：30 轮会议上下文有界；关键决策保留。
- 测试：长会话模拟；压缩幂等。

### 阶段 3 · 审批/澄清路由

- 内容：`request_interaction` / `resolve_interaction` / `expire_interactions`（随心跳过期）；`POST /api/meetings/interactions/respond` 幂等（已响应返回 stale）；事件负载契约 `{type:"approval", interaction:{id,agent,question,choices,expires_at}}`。
- 验收：请求→弹窗→响应→过期全路径；重复响应 stale。
- 测试：幂等/过期/越权。

### 阶段 4 · SSE 实时推送

- 内容：`/api/meetings/events?session_id=`（独立线程订阅表，复用 _sse）：事件 `message/status/approval/heartbeat`；无事件 15s 心跳；连接清理。
- 验收：双客户端同收；推送期间 `/api/control` 可响应（非阻塞）；断线重连拉全量补齐。
- 测试：MockEventSource；连接上限与清理；阻塞验证。
- 审查：线程安全专项。

### 阶段 5 · 前端聊天室

**步骤 5.1 房间视图骨架**：消息流（虚拟列表 + 增量渲染）+ 底部输入（@插入下拉）+ 四态完整。
**步骤 5.2 @插入与审批弹窗**：`@` 弹参会编辑列表；审批事件弹审批卡（同意/拒绝/暂缓 + 倒计时）。
**步骤 5.3 模式切换与状态轨道**：发起时选 rounds/free；free 直播头显示思考中编辑（头像脉冲）+ 队列长度；保留推进/结束/取消；SSE 接入。
- 验收：交互测试 + 视觉截图；impeccable detect 清零。

### 阶段 6 · 上下文压缩增强

- 内容：token 阈值触发压缩（默认 120k 字符）+ 尾截断策略可配 + 压缩事件 `status:compressing`。
- 验收：500+ 消息模拟会议不超预算；压缩后决策/待办可检索；重复触发不二次压缩。

### 阶段 7 · 全量回归与真实验证

- 内容：dry-run 端到端（mock LLM + 临时库）跑通六场景；真实会议一次（用户在场）；`run_review.ps1 -Scope slices` + 修复闭环。
- 验收：后端全量绿、前端 40+ 测试绿、build 绿；P0/P1 清零；六场景逐条打勾。

### 阶段 8 · 文档与部署

- 内容：README 会议章节、backlog 更新、审查归档；提交推送（用户确认后收尾，不写敏感信息）。

## 3. 老板汇报节奏

- 每步完成：一句话「做了什么、验证了什么」。
- 每阶段完成：四要素汇报 + 六场景打勾进度。
- 阶段 7 真实会议前：约时间演示关键 4 场景（自由接龙/@必答/审批/断线恢复）。

## 4. 最终验收标准

1. free 模式无人 @ 自然接龙；沉默权生效；冷却/上限/熔断生效。
2. @必答、老板插话、审批弹窗、主席总结落盘全部可用且实时（SSE）。
3. 长会议上下文有界；rounds 周会零回归；断线/重启消息不丢不重。
4. 前端 40+ 测试、后端全量测试、impeccable 门禁全绿；六场景逐条可复现。

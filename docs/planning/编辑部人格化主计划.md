# 文学编辑部 · 人格化主计划（Master Plan）

定位：项目已从「AI 流水线」升级为「文学编辑部」。目标是让 11 位 agent 从
「有性格的执行器」变成「有动机、有记忆、有关系、会主动协作的编辑」。

核心原则：

- 外部节拍负责「开门」（手动开工为主、定时可选），编辑部内部由
  任务板、承诺、消息、关系、反馈共同驱动。
- 调度器退到安全底线：触发、质量门、发布、预算、存稿策略不可绕过。
- 每步小步交付，全量回归 279 后端 + 8 前端，可回退。

## 一、四大系统总表

| 系统 | 现状 | 目标 | 载体 | 落库 | 注入时机 | 验收标志 |
| --- | --- | --- | --- | --- | --- | --- |
| 记忆 | 故事记忆（writing_context）+ 每日/每周日记；无自我事件记忆 | agent 记得自己说过/做过/承诺过，观点随时间演化 | 快照文本 | `agent_memories`（新）+ 现有 `agent_diaries`/`agent_activity` | 每次 LLM 调用注入最近记忆 | 写手记得上周被审稿打回过并主动改进 |
| 关系 | 无 | 亲疏、信任、摩擦随事件变化，影响协作语气与决策 | 关系快照 | `agent_relations`（新） | 每次 LLM 调用注入 | 打回多了摩擦上升；提案被采纳信任上升 |
| 消息 | 无 | 可留言、回复、转交、催稿、道歉 | 收件箱/outbox | `agent_messages`（新） | 每次 LLM 调用注入收件箱，输出 outbox 落库 | 审稿可给写手留言说明理由，写手回复 |
| 驱动 | 纯外部 push：调度器/会议状态机 | 外部节拍开门 + 内部任务板/承诺/消息/反馈/关系共同驱动 | 任务板 + 承诺 + 收件箱 | `agent_actions`（升级）+ `agent_promises`（新） | 开工分派、认领、承诺兑现检查 | 主编分派活，写手认领并按时兑现 |

## 三、自由度表（限制 → 解锁 → 底线）

| 限制点 | 现状 | 解锁方案 | 底线（不可放开） |
| --- | --- | --- | --- |
| 调用序列 | 调度器固定 A/B 双轨 | 主编按情况点将（editorial 模式，fixed 可回退） | 质量门+合规+预算熔断 |
| 协作通道 | 无 | mailroom 消息总线 | 消息不直接触发外部发布 |
| 会议形式 | 固定三轮+主席总结 | 先插话、后自由对话，主席点名/收束 | 周会报告必须落库留痕 |
| 决策 | 权重固定 | 人格立场+关系+证据综合 | 成本与平台规则硬约束 |
| 触发 | 手动/定时 | 手动为主+定时可选；编辑部内部可自主开小会 | 建书/发布/删书受控 |
| 任务承接 | 调度器派活 | 任务板认领 + 替代方案提议 | 日更数量与存稿策略由调度器守底 |

## 四、驱动模型表

## 五、性能与成本表

| 项目 | 估算 |
| --- | --- |
| 注入开销 | 每次调用 ~1.6K token（收件箱 8×200 字 + 记忆 3×150 + 关系 3×80 + 承诺 3×100 + 待办 3×100） |
| 日更月增量 | ~3.5–4.5 元（注入 3.3 + 分派/打回/会议余量），占 100 元预算 ~4% |
| 按 agent 过滤 | 只给写手/审稿/主编/记忆官注入 → 再省 ~40% |
| LLM 调用次数 | 消息/承诺/关系全部落库零额外调用；提炼合并进周记一次调用 |
| 延迟 | 单次 prompt +1.6K token，延迟增加数秒，对日更总时长无感 |
| 熔断 | 预算熔断 + 重试上限 + 打回轮次上限，成本不可失控 |

## 七、检查点与纪律

- 每步跑 `python run_tests.py`（279+）+ `cd webapp && npm test && npm run build`。
- 修 bug 先写失败测试；新表走 `_migrate` 幂等；大 payload 走文件；中文全链路 UTF-8。
- 高风险步骤（S10/S13）保留固定模式开关，灰度验证后再默认。
- 每阶段结束更新本计划与 README，数字与代码一致。

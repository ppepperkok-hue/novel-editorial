# 会议系统改造：最终评估报告（自由会议 · 自主发言调度器）

## 1. 结论摘要

自由会议采用「事件驱动 + 自主接话 + 沉默权 + 主动议题 + 主席调停」模型，在我们现有 Python + React 栈上**成立**。核心基础设施已验证可用：服务器是 `ThreadingHTTPServer`（web_api.py:11,1232，SSE 长连接不阻塞其他请求）；异步会话已有后台线程先例（`start_session_async`，meeting_session.py:863）；agent 调用支持每线程独立数据库连接（agent_tool_loop.py:193 `run(..., db_path=...)`），可并行；LLM 调用有重试（agent_meeting.py:188）与成本记录。

但有 **6 处必须调整或显式降级**（详见第 3 节），否则「自由」会变成「失控」或「假自由」。调整后按《会议系统改造·工程表》分阶段实施。

## 2. 目标与效果预期

改造完成后必须真实可跑（dry-run 与真实各一次）：

1. 发起自由会议（如「讨论下一卷剧情」），**无人 @、无人点名**：文策抛方向、守正主动质疑、墨白补细节、阿读从读者视角插话——自然接龙，界面实时滚动，可见「墨白正在思考…」。
2. 老板插话 `@守正 说说你的顾虑`：守正必答；相关编辑可继续接，不相关的不必开口（沉默权）。
3. 讨论跑题或冷场：主席主动拉回 / 有编辑抛新话题 / 主席推进，30 秒内必有动作。
4. 编辑请求拍板：面板弹审批卡，老板同意/拒绝/暂缓，编辑收到结果继续。
5. 老板说「总结一下」：主席当场输出报告，行动项落盘。
6. 长会议不爆上下文；固定轮次周会零回归；刷新/断网后消息不丢不重、会话可恢复。

### 3.2 必须调整项（自由会议的真实约束）

| # | 问题 | 调整方案 | 影响 |
| --- | --- | --- | --- |
| A1 | 现有 `run_session` 是同步跑完整会议（点将→逐轮→总结），自由会议不能复用「推进一轮」语义 | free 模式新写**事件循环线程**：接收事件（用户消息/@/审批/冷场）→ 接话决策 → 并行发言 → 广播 → 等待；`advance_session` 在 free 下语义改为「投递事件」；rounds 路径零改动 | 双路径并存，状态机必须分支隔离 |
| A2 | 冷场计时器依赖进程存活；重启后 free 会话「看起来在跑实则没线程」 | 事件循环线程内置冷场计时；web_api 启动时扫描 `status='running'` 的 free 会话标记 `interrupted`（fail-closed），前端提示可重新发起；消息表持久不丢 | 恢复语义必须显式，不许假绿灯 |
| A3 | 沉默判定不可靠：LLM 输出 `{speak:false}` 解析失败会被误判 | 发言输出解析失败 → 重试一次 → 再失败按 `skip` 处理但落 `no_speech` 事件留痕（audit_logs），绝不静默 | 反模式族 F3/F4 红线 |
| A4 | 相关性预筛的精度上限 | v1 用「关注点关键词 ∩ 话题」轻量打分 + 必答名单，不做 LLM 预筛（成本低、可测）；效果上限低于 LLM 判断，列为 v2 升级点 | 如实标注：接龙自然度受预筛质量限制 |
| A5 | 自动跑题检测成本高 | v1 不做 LLM 高频跑题判断；主席参与策略：冷场推进 + 用户「拉回/总结」指令 + 可选每 N 条消息主席插话（N 可配） | 明确 v1 边界：跑题拉回主要靠主席冷场策略与老板喊话 |
| A6 | 自由会议历史增长快，压缩不能放在最后 | 基础尾截断（最近 N 条 + 字符上限）与摘要锚点**随阶段 2 一起交付**；token 阈值增强压缩放阶段 6 | 工程表顺序调整 |

### 3.3 新增风险清单

| 风险 | 等级 | 缓解 |
| --- | --- | --- |
| 成本失控：每事件最多 3 次候选调用，50 轮约 150 次 flash 调用 | P1 | 单会议费用/调用上限（settings 可配），超限自动停止自主发言并提示主席；成本全部落 cost_logs 可查 |
| 同 agent 并发/刷屏 | P1 | 会话级锁 + 每 agent 状态（busy/冷却）+ 最小发言间隔（默认 60s）+ 每事件接话上限（默认 2+@数） |
| SSE 断线丢事件 | P1 | 前端重连后拉全量消息补齐（消息表为准）；事件为可重建状态而非唯一真相 |
| 并行调用打满 DeepSeek 并发限制 | P2 | 并行池 `max_workers=K`（默认 3），串行重试退避已有 |
| 会议线程与日更/workday 线程竞争 | P2 | 自由会议独立 session，不进入日更锁；workday 决策点仍由用户触发 |

## 4. 架构决策（最终）

1. **不引入 Node/Socket.IO/Vue**：hermes 仅作算法与交互参考；实时推送用 SSE（ThreadingHTTPServer 已满足）。
2. **事件驱动发言模型**：事件类型 `user_message / agent_message / approval_resolved / cold_timer`；被 @ 必答 + 相关性预筛 top K + 沉默权 + 冷却与上限保险丝。
3. **执行器桥**：新写 `meeting_executor.py`，经 `agent_tool_loop.run`（人格 + 记忆快照 + 知识工具）或 `agent_meeting.ask` 组装会议上下文（材料 + 历史尾截断 + 该编辑周记/心情 + 事件消息），输出六段结构或 `{speak:false}`。
4. **数据层**：`meeting_messages`（增量）、`pending_interactions`（审批）、`meeting_sessions.mode`（rounds/free）；旧 transcript 兼容回退。
5. **压缩前置**：阶段 2 交付尾截断 + 摘要锚点；阶段 6 交付 token 阈值增强。
6. **恢复语义**：启动扫描 running→interrupted；消息持久为唯一真相；SSE 只作增量通知。
7. **主席角色**：free 下为调停者（冷场推进/用户指令总结/可选周期插话），不做自动跑题检测（v1 边界）。

## 5. 假设与默认

- `mode` 默认 `rounds`；free 为增量能力，可开关，参数全部进 settings。
- v1 不做：LLM 相关性预筛、自动跑题检测、周记 concern 自动注册议题（冷场由候选编辑自主抛话题代替）；三项列为 v2。
- 转交链（handoff）不在本次范围。
- hermes `mention-routing` 逻辑参考移植时标注来源与许可。
- 所有改动在 `codex/frontend-redesign` 分支，分阶段提交，收尾合并待用户确认。

# 编辑部工作日设计（Editorial Workday）

## 一、语义升级：开工 = 上班，不是跑任务

现在的「开工」语义是「跑一次日更任务」：执行章节生产链，写完就结束。这带来三个问题：

1. **没有「一天」的轮廓**：0.6 秒跑完的日更让人不舒服，不是因为快，是因为 agents 没有任何工作痕迹就消失了；
2. **拟人化是装饰**：记忆、关系、情绪、日记、议题都围着一次任务转，agents 不过日子，就没有连续性；
3. **产出与生活脱节**：存稿够时 agents 无事可做，而真实编辑部里不赶稿也在上班——回消息、整理稿子、聊问题。

升级后的语义：**开工 = 编辑部上班（进入一个工作日）**。章节只是这一天的主产出，不是全部。工作日有完整节律：开工打卡 → 晨会分派 → 主产出 → 协作时段 → 收工（两级完工）。每天留下日记、待办、遗留、议题，第二天带着回来。

## 二、工作日生命周期

```
idle（待命）→ 开工 → morning（晨会/分派）→ producing（主产出）→ collaborating（协作时段）→ closing（收工）→ done / done_with_pending / partial / failed
                                                              ↑___________________________|
                                               （昨天有遗留：开工晨会先带出，优先处理）
```

| 阶段 | 做什么 | 成本 | 触发 |
| --- | --- | --- | --- |
| `idle` 待命 | 编辑部门关着；消息/议题池可以积累，零 LLM 成本 | 0 | 默认状态 |
| `morning` 晨会 | 主编看任务板、收件箱、承诺、昨日遗留 + 老板今日指令 → 宣布今日安排；无任务则宣布「今日以整理/协作为主」 | 1 次 flash（eic） | 开工自动 |
| `producing` 主产出 | 现有章节生产链：大纲→写→润→审→读者审→终审→质量门→发布；支持多章、存稿优先、A/B 轨 | 现有成本 | 晨会安排有稿则执行 |
| `collaborating` 协作 | 处理收件箱、兑现承诺、投议题、更新人物卡/知识库、行动项回填 | 1~2 次 flash（可开关） | 主产出后自动（collab_on，默认开） |
| `closing` 收工 | 全员写当日日记（含 mood）→ 明日待办 → 收工广播（eic 发公告）→ 状态落库 | 日记已有 + 1 次 flash 广播 | 两级完工自动 / 老板手动收工 / 超时兜底 |

## 三、两级完工状态机（workday 终态）

| 状态 | 含义 | 老板在面板上看到 |
| --- | --- | --- |
| `done` | 主产出完成 + 协作收工全部完成 | 今天的工作做完了，收工时间、产出、待办清晰 |
| `done_with_pending` | 主产出完成，但有协作/收尾遗留（如某条消息没处理、某章待补发） | 收工了，但标「有遗留」，明天优先处理 |
| `partial` | 主产出部分完成（如 A 轨发布失败、一章没过审） | 今天没全做完，失败原因可见，明天开工先续 |
| `failed` | 整日异常（预检不过、整批无产出） | 显式告警，不静默；明天开工自动带出原因 |

关键规则：**主产出完成 ≠ 下班**。交稿之后还要走协作和收工，一天才算结束；有遗留就如实标出，不硬撑、不掩盖。

## 四、老板指令：开工时可以决定「今天干什么」

开工不是只能写稿。面板开工按钮旁可选今日主题：

| 今日主题 | 工作日怎么排 |
| --- | --- |
| 写稿 N 章 | 晨会 → 主产出（N 章，存稿优先）→ 协作 → 收工 |
| 整理日 | 晨会 → 无主产出 → 协作时段延长（回消息、整理知识库、更新人物卡、投议题）→ 收工 |
| 开会 | 晨会 → 会议（周会/专题/会诊等，挂接会议系统）→ 协作 → 收工 |
| 自由 | 主编根据任务板、承诺、遗留自行安排今日轻重 |

这样写稿、开会、整理全部统一在「一天」的语义下，会议系统（当前暂缓的方案）以后可以作为「今天的内容」自然接入，不用另起炉灶。

## 五、与现有系统的衔接（复用优先，不推倒重来）

| 现有部件 | 如何复用/升级 |
| --- | --- |
| `tools/editorial_daily.py` | `daily()` 主体原样保留，包装为 workday 的 `produce` 阶段；入口函数改为 `workday.open(conn, chapters=None, trigger, boss_instruction="", dry_run)` |
| `daily_runs` 表 | 语义从「一次日更」升级为「一个工作日」，幂等新增字段：`phase`（当前阶段）、`boss_instruction`（今日主题）、`today_plan`（晨会安排 JSON）、`collab_summary`、`legacy`（昨日遗留）；`run_id` 即 workday_id |
| `preflight` 原子锁 | 原样复用，注释语义从「日更锁」改为「工作日锁」；跨进程只允许一个工作日，陈旧回收/全路径释放逻辑不变 |
| `write_diaries` | 原样复用，并入 `closing` 阶段（写当日日记含 mood） |
| `mailroom` | 收工广播 = eic 发一条 `kind='broadcast'` 公告；协作时段读收件箱/outbox 沿用现有注入 |
| `services/control.py` | `run_now` 改为调 `workday.open`；`load_control` 返回工作日状态（idle/working/phase/终态）；`daily_enabled` 开关语义不变 |
| `auto_fill_actions` / `relations` / `novel_knowledge` | 协作时段按需调用，全部现有函数 |

## 六、恢复与防挂起

- **昨天没干完**：`partial` / `done_with_pending` 的 workday 是今天开工的默认输入——晨会先带出遗留清单，主编优先分派。
- **中途断电/重启**：沿用现有陈旧回收（running 超时视为死锁释放），workday 状态落库可回看。
- **收工兜底**：不设硬性下班时间，但提供 `max_work_hours` 配置（默认关），开启后到点自动收工并标 `done_with_pending`，防挂起。
- **待命不消耗**：不开工就不产生任何 LLM 调用；消息和议题在库里积累，面板可见。

## 七、前端改动

1. 首页状态卡：待命 / 工作中（显示当前阶段：晨会、写稿、协作、收工）/ 已收工 / 有遗留；不再只显示「运行中/待命」这种模糊状态。
2. 开工按钮旁：今日主题选择（写稿 N 章 / 整理 / 开会 / 自由）+ 开工后显示阶段流转。
3. 收工后卡片：今天做了什么（产出、协作摘要）、明日待办、遗留清单。
4. 执行记录页：按工作日展示，可看每个阶段的耗时与失败节点。

## 八、成本评估

| 项目 | 估算 |
| --- | --- |
| 晨会 | +1 次 flash（eic），约几百 token |
| 协作时段 | +1~2 次 flash（默认开，可关），约几百 token |
| 收工广播 | +1 次 flash（eic 公告） |
| 日记 | 已有（全员日记），不新增 |
| 每班新增 | 约 3~5 次 flash，估 ¥0.1~0.3/班，相对写稿成本可忽略 |
| 空班/整理日 | 无主产出时成本反而更低（无章节链），协作是唯一开销 |

## 九、测试计划

- 状态机全路径：写稿班、空班（整理日）、异常班（整批失败）；
- 两级完工四态：`done` / `done_with_pending` / `partial` / `failed`；
- 锁并发：工作日进行中再次开工只跑一个；
- 遗留恢复：昨天 `partial` → 今天晨会材料含遗留清单；
- 老板指令解析：写稿 N 章 / 整理 / 开会 / 自由 四种分派断言；
- 阶段落库：`phase` 随流转更新，失败时 `failed_nodes`/`error` 显式；
- 前端：状态卡、主题选择、阶段流转、收工卡片测试；
- 全量回归：371 后端 + 15 前端基线保持全绿。

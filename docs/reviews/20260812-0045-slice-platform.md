Two P1 defects break core flows outright: collect_reader_stats.py crashes on every CLI invocation (undefined ENV_FILE), and delete_book.py's local purge always fails with an FK IntegrityError after the Fanqie book was already deleted remotely, leaving local state permanently inconsistent. Several P2 robustness/dependency issues (unhandled URLError, stealable daily lock, string-summary crash, pending_publish loss, missing websocket-client) also need fixing.

Full review comments:

- [P1] collect_reader_stats CLI always crashes on undefined ENV_FILE — E:\code\novel-editorial\tools\collect_reader_stats.py:133-133
  tools/collect_reader_stats.py:133 references `ENV_FILE` in `ap.add_argument("--env-file", default=str(ENV_FILE))`, but the module never defines it (it only defines `OUT_CSV`/`UA`). Reproduced: `python tools/collect_reader_stats.py --db demo.db` dies with `NameError: name 'ENV_FILE' is not defined` at line 133 before any work happens, so the CLI/n8n path can never collect reader stats. The library entry `run()` still works; fix by defining `ENV_FILE = Path.home() / ".n8n" / ".env"` (as preflight.py does) or removing the argument.

- [P1] delete_book local purge always fails with FK IntegrityError — E:\code\novel-editorial\tools\delete_book.py:43-52
  `_purge_novel` (tools/delete_book.py:43-52) deletes every table having a `novel_id` column, but iteration order hits `chapters` before its child tables and `db.connect()` enables `PRAGMA foreign_keys=ON` (novel_editorial/db.py). Any novel with published chapters (publish_logs/chapter_content/chapter_summaries/quality_reports/world_events reference chapters.id) makes `DELETE FROM chapters` raise `sqlite3.IntegrityError: FOREIGN KEY constraint failed` — reproduced with a minimal novel holding two published chapters (purge failed, rows intact). Since the Fanqie book is deleted remotely first, the crash leaves the local novel bound to a book that no longer exists, and retry cannot succeed (remote book_detail/delete will fail). Delete chapter-scoped children first (or disable FK during purge); agent_messages (ref_novel_id) and chapter-scoped rows are also never purged.

- [P2] delete_book lets URLError/HTTPError escape and crash — E:\code\novel-editorial\tools\delete_book.py:83-87
  `delete_book_on_fanqie` wraps the HTTP calls in `except (RuntimeError, ValueError)` only (tools/delete_book.py:83-87), but `http_json` (tools/create_book.py) raises `urllib.error.URLError`/`HTTPError` on network failures. Reproduced: with `http_json` raising `URLError`, the exception escapes instead of returning `{"ok": False, "error": ...}` — a DNS/timeout/TLS failure produces a traceback and any panel caller gets an unhandled exception, unlike create_book.py which catches this same class. Add `urllib.error.URLError, urllib.error.HTTPError` to the except clause.

- [P2] preflight lock is stealable: recorded PID is the exiting preflight process — E:\code\novel-editorial\tools\preflight.py:122-126
  `acquire_lock` writes its own `os.getpid()` (tools/preflight.py:124), but in the n8n path (n8n/novel_workflow.json runs `python tools/preflight.py --db demo.db` at start and `tools/release_lock.py` at the end) that process exits right after acquiring. The stale check (lines 139-147) then treats any lock whose PID is dead as stale — reproduced: a 10-second-old lock with a dead PID is unlinked and re-acquired — so a second run starting while the first run is still in progress steals the lock, both pass preflight, and both can publish (the double-publish the lock exists to prevent). The docstring's "lock younger than 2h is considered held regardless of PID" contradicts the code, which only applies the 2h rule when the PID cannot be parsed. editorial_daily.py's in-process use is unaffected; the n8n path is vulnerable.

- [P2] record_work crashes when chapter summary is a plain string — E:\code\novel-editorial\tools\record_work.py:222-222
  `_upsert_summary` explicitly supports string summaries (`summary.get("summary") if isinstance(summary, dict) else str(summary)`, tools/record_work.py:126) but later unconditionally calls `summary.get("foreshadowing_planted")` at line 222, raising `AttributeError: 'str' object has no attribute 'get'` — reproduced with `{"summary": "纯文本总结"}`. When the n8n 整理剧情 node yields raw text, `record_work` crashes mid-run after chapters were already persisted, so the activity log and cost summary are skipped. Apply the same isinstance guard to the dict-only branches.

- [P2] pending_publish cleared before publish attempt; request silently lost on failure — E:\code\novel-editorial\tools\publish_stock.py:363-367
  publish_stock.py main() reads `pending_publish` and immediately resets it to '0' (lines 363-367) before `publish_batch` runs. If every chapter fails (cookie expiry, network error, platform rejection), the panel-requested catch-up publish is consumed with no alert and no retry — unlike preflight.py, which deliberately keeps `manual_run_requested` until the run actually proceeds (tested in tests/test_preflight_guard.py). Reset the setting only after at least one chapter is published, or restore it on total failure.

- [P2] websocket-client undeclared; inject_fanqie_cookie fails in project venv — E:\code\novel-editorial\pyproject.toml:10-10
  scripts/inject_fanqie_cookie.py:8 does `import websocket` (websocket-client), but pyproject.toml declares `dependencies = []` (line 10) and the package is absent from uv.lock and the project `.venv` — reproduced: `.venv\Scripts\python.exe -c "import websocket"` → `ModuleNotFoundError` (only the system Python has it). A fresh `uv sync` environment cannot run the cookie-injection script. Declare `websocket-client` in pyproject.toml and re-lock, or vendor the parsing.

- [P3] check_stock --novel-id never wired to CLI (multi-book isolation unreachable) — E:\code\novel-editorial\tools\check_stock.py:88-88
  `check_stock(conn, novel_id=0)` supports per-novel stock scoping ("multi-book isolation" per its docstring), but `main()` calls `check_stock(conn)` with no CLI flag (tools/check_stock.py:88), so the n8n command always counts reviewed chapters across ALL novels while returning metadata of the latest publishing book. In a multi-book setup `need` is under-counted (other novels' stock inflates the pool), which can skip generation for the active book. Add a `--novel-id` argument and pass it through.

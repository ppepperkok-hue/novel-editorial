- Kill spawned pythonw child when ensureApi startup times out — E:\code\novel-editorial\desktop\main.js:115-128
  `ensureApi()` (desktop/main.js:115-128) polls `apiReady` for 20s after spawning pythonw, then throws; the `app.whenReady` catch (desktop/main.js:346-356) sets `apiStopping = true`, shows the error dialog and calls `app.quit()`, but never terminates `apiProc` — and since `createWindow()` was never called, the `win.on("closed")` cleanup that kills the child never runs. If the pythonw process is still alive but its API failed to become ready within 20s (e.g. DB locked, slow import, port half-occupied by another service), it survives as an orphan process holding port 8000. On the next launch the app either reuses that half-dead instance (apiReady succeeds against a broken handler) or the freshly spawned process exits immediately with a port conflict, entering the restart loop — contradicting the dialog text "请确认...端口 8000 未被占用". This path was rewritten in this commit (spawnApiProcess/apiStopping), and the fix is a one-line `if (apiProc) apiProc.kill()` in the catch block.

## 第 1 层：核心价值（01a）

### 一句话价值主张

为作者解决「分歧攒到火气见底还要我亲自点将开会」的问题，带来「审稿被压到耐心耗尽时，编辑部自己把讨论开起来、点好人、通气、总结，作者旁听、随时拍板」的结果，让协作链真正能自然走动。

### 核心用户与核心场景

- 作者本人：审稿三次指出矛盾都被压下，耐心池见底，编辑部自动召集一轮讨论（写手与审稿对质、主编通气总结），事件流全程可见，作者随时介入拍板；讨论没解决就冷却后重新攒，不会死缠烂打。
- 开源外部作者（次）：默认保守旋钮下，触发阈值与冷却温和，开箱可预期。

### 价值边界（明确不解决）

- 不解决无人监督的创作链自走：讨论是协作链，只产生对话与留痕，不写正文、不改稿、不自动拍板。
- 不做定时器、工作日节拍、固定晨会（红线不变）；触发是事件驱动的。
- 不解决讨论内容的 LLM 自由发挥（复用 N4 确定性模板 + N28 提炼开关的既有口径）。

### 反盲从三问

1. 需求还是方案？「分歧攒到阈值编辑部自己开讨论、作者旁听拍板」是需求；耐心池见底触发 + 冷却 + 点将模板是方案。
2. 依据是什么？回溯 G1（协作自然发生）、G3（伙伴完整度）与 09 收口补充「状态阈值三状态 / 见底触发行动 / 清零进冷却」；N4 讨论形态是底座。
3. 不做会怎样？自然行为停在「会选、会变」而没有「会自己动起来」，协作链自走缺最后一块。

### 做 / 不做

**做（N29）**：耐心池见底的事件驱动触发（挂在既有业务事件后）、自然召集的点将模板（分歧双方 + 主编）、触发后池清零与议题冷却、未解决重新攒、事件流与 CLI 可见、文档与收口。

**不做（N29）**：创作链自动推进（讨论不写正文）、定时器 / 后台调度、讨论内容 LLM 自由发挥（沿用 N4 模板）、面板可视化（后置面板阶段）。

### 依赖与实施顺序

触发判定（池底 + 议题冷却）→ 自然召集（点将 / 通气 / 总结 / 落盘）→ 清零与冷却 → 可见性与文档 → 全量回归与独立审查。

## 全局约束与风险

- 约束：延续全部红线——不工单化、不强制、作者永远拍板、可解释、可复现；讨论是协作链不碰正文；触发事件驱动、无定时器。
- 风险 1：触发风暴 → 议题级冷却 + 池清零 + 触发上限（防同议题反复开会）。
- 风险 2：自然召集偏离 N4 形态 → 复用 discussion 既有接口与确定性模板，只加触发层。
- 风险 3：作者被讨论淹没 → 事件流可见 + 作者拍板即收敛（复用 N28 冲突中和）。
- 决策记录：自然召集是协作链的自走终点，创作链依旧由作者把守。

### 问题

#### Important（应该修）

1. src/novel_editorial/core/proactive.py:134-143 — 单次评估内同 agent 多 spec 超预算
   问题：每个 spec 都重新查同一份已用计数，两个同 agent 的 spec 条件都满足时，即使剩余预算只有 1 也会返回 2 个候选。
   影响：调用方按返回候选写消息会超发，频次上限承诺失效。
   修法：在评估循环内按 agent 追踪剩余预算，每 append 一个候选扣减一次。

2. src/novel_editorial/core/proactive.py:104-110 — rebuttal 等非主动消息消耗频次预算
   问题：`%"kind":%` LIKE 会命中任何带 kind 的 payload，draft.py 写入的 {"initiator": "agent", "kind": "rebuttal"} 被误计。
   影响：写手几次修订就把默认预算 3 耗尽，主动汇报/追问静默不触发。
   修法：只统计 kind 属于 PROACTIVE_KINDS 五类的消息。

#### Minor（可后补）

3. src/novel_editorial/core/config.py:67-73 — 负数 proactive_max_per_agent 静默禁用
   问题：int() 接受负数，之后计数与负数上限比较永远 False。
   影响：主动行为被静默关闭，违背失败显式化纪律。
   修法：解析后小于 0 抛 CONFIG_ERROR。

### 建议
